# 前端页面与后台动态维护对照

2026-10-22 · 交给博达模板与后台接入同学。页面核对基线：`main@4a7d456`。本文是已确认的维护需求与页面定位表，不表示学校博达已经配置完成。

**学长先看第 2～5 节：这些就是需要模板化、接入后台的页面和位置。** 页面链接指向仓库静态预览，便于对照外观；正式地址和博达栏目编号由学校平台提供。部署和平台配置仍从[后端交付主文档](../后端交付文档_博达接入与预览部署.md)进入。

## 1. 已确认范围

| 项目 | 本次要求 |
|---|---|
| 实施平台 | 学校博达站群，由后端同学配置栏目、资料源和模板 |
| 固定不变 | 现有导航名称、层级、顺序、各页区块位置、栏目标题、中英文装饰标题、版式、颜色、动效；本次不做管理员自由增删网站栏目功能 |
| 后台可维护 | 全站业务内容，包括文章、教师、机构、科研、仪器、轮播、首页介绍、联系信息、二维码与友链；记录可新增、修改、排序、发布及撤下 |
| 同一资料多处展示 | 只录入一次，首页、概览、列表、详情读取同一份已发布资料；首页支持推荐和排序，轮播独立维护 |
| 文件 | 在学校平台上传、选择和替换图片、附件，维护图片说明和附件名称；文件格式、大小、存储路径按实际平台配置 |
| 发布 | 保存草稿、预览、发布、撤下；修改草稿不得提前改变公开内容；是否需要审核、由谁审核按学校流程配置 |

“内容排序”指新闻、教师、轮播等记录的顺序，不是调整导航或页面区块顺序。管理员可以增减某栏目的文章或教师记录，不应自行新增一种页面布局。

本文中“当前”来自代码核对，“接入要求”是要在博达实现的目标，“建议默认”是供实施采用的规则，可与学长核定；博达能力、组件标签和字段名未经实测，不猜测接口地址或栏目 ID。

## 2. 全站公共部分

| 编号／页面位置 | 后台维护内容 | 共用与显示规则 |
|---|---|---|
| G01 所有页面顶部品牌区 | 学院正式中文名称、英文名称、校徽/标识、图片替代文字、校训 | 一份站点资料供全站引用；需学院确认后更新，不改变排版和菜单名称 |
| G02 所有页面页脚 | 学院名称、英文名称、校训、正式备案文字；与 G01 共用的标识 | 备案信息未提供时不伪造；技术支持文字、工作室链接及图标本次保持模板固定 |
| G03 页脚及联系页公众号 | 正式二维码图片、显示名称、说明、启用状态 | 一处上传，两处一致；启用但缺图时保留现有“二维码待提供”框；停用则隐藏 |
| G04 页面中业务图片与附件 | 图片、alt 替代文字、图注；来源名称/链接、授权记录；附件文件、显示名称及排序 | 原文件与使用位置关联；共享图片替换应核对所有引用位置。图片加载反馈、比例和裁切由现有组件控制 |

公共导航、面包屑、“查看全部”、返回入口、网站地图从固定栏目映射输出；链接换成博达实际地址，不要求编辑员每页手填。内页芯片横幅、背景大字、按钮和动画是模板装饰，本次不建日常业务资料源。

## 3. 首页：逐块接入

页面：[首页](../frontend/preview/index.html)。轮播下方依次是新闻、通知、科研、培养、师资五个区块，位置保持不变。

| 编号／可见位置 | 后台维护字段或来源 | 展示与复用要求 |
|---|---|---|
| H01 顶部六张主题轮播 | 单独的轮播记录：图片、替代文字、主标题、英文眉题、说明、副说明/图注、顺序、启用状态、发布状态 | 当前为六张，数据层支持按启用及排序输出；圆点和计数随实际显示数量变化。不能把序号作为记录身份；不新增自动跳转，当前轮播没有业务跳转链接 |
| H02 [学院新闻区](../frontend/preview/index.html#home-news) | 从新闻库引用：标题、发布日期、封面、封面说明/图注、详情地址；另设首页推荐与推荐排序 | 最多 4 条；文字列表与右侧图片新闻使用同一批记录且一一对应，不能分别维护两套标题。正文只在新闻库维护 |
| H03 [通知公告区](../frontend/preview/index.html#home-notices) | 从通知库引用：标题、摘要、发布日期、详情地址；另设首页推荐与推荐排序 | 最多 3 条；序号由模板产生；通知撤下后不能继续留在首页 |
| H04 [科学与创新区](../frontend/preview/index.html#home-research)的介绍与两个栏目入口 | 大段引导语、介绍摘要；研究平台/课题组入口摘要；配图与图注、来源说明 | 当前为首页配置，不是最新文章流。入口名称和目标保持现有栏目；与内页相同的资料直接引用，首页专用短文案作为独立配置，不复制完整正文 |
| H05 科研区下方三张图文 | 当前“走近晶圆与芯片”“微纳加工与实验”“认识半导体器件”的展示标题、图片、替代文字、图注、来源链接 | 保持三个位置及当前目标栏目：研究方向、研究进展、人才培养。文字区可点击、图片不跳转、来源链接独立。若引用已有资料，图片与正文来源共用；不另录一份业务记录 |
| H06 [人才培养区](../frontend/preview/index.html#home-education) | 引导语、介绍摘要、学科与专业/课程与培养方案入口摘要、图片、替代文字、图注和说明 | 保持两个栏目入口及版式；介绍性内容可单独维护，已有专业、培养方案正文引用相应栏目资料 |
| H07 [师资队伍区](../frontend/preview/index.html#home-faculty) | 教师库中的姓名、职称、照片、摘要、详情地址；首页推荐与顺序；区块说明文字 | 最多 3 位，按教师稳定身份去重。一人有多个称号也只显示一次；修改或撤下教师同步影响首页、分类与名录 |

**首页推荐需要新增平台配置。** 当前新闻/通知默认按日期，教师默认按最高有效人才类别优先级、人工顺序、稳定 ID 排序；代码没有已接通的博达推荐后台。建议默认：先取已发布且推荐的记录，按推荐顺序；不足数量再按原默认规则补足，去重且不补草稿、撤下内容或演示数据。新闻图片不足时使用已有缺图反馈，不捏造新闻配图。该默认规则由学长在接入时落实并验收。

科研、培养不是新建一套文章库：平台可用首页固定图文配置加已有资料引用实现推荐与选取，仍保留当前布局及目标栏目。未来若要将其改为“最新科研文章列表”，属于另一次页面需求变更。

轮播全部停用时不得回填已撤下内容；建议保留不带宣传文案的现有背景作为空态并隐藏轮播控件，具体空态需接入时预览核对。切换时长、动画、字体主题仍由前端控制，不要求编辑员配置 CSS 类。

## 5. 每类记录需要哪些字段

这些是业务字段要求，不是数据库表名或博达字段标签。平台内置标题、日期、正文等字段优先复用，缺少的扩展字段由学长确认实现。

| 记录类型 | 发布前必须具备 | 适用时填写／按需展示 |
|---|---|---|
| 新闻、通知、一般文章 | 稳定身份、所属固定栏目、标题、发布日期、有效正文或正式文件、发布状态、平台详情地址 | 摘要、封面、正文图片、alt、图注、来源、附件；首页推荐及排序 |
| 单篇介绍 | 固定位置身份、有效正文、发布状态 | 小标题、图片、图注、来源、附件；不要求伪造发布日期 |
| 机构/方向/平台/课题组/仪器条目 | 稳定身份、归属集合、名称、有效介绍、发布状态、顺序、平台详情地址 | 表内专业内容、摘要、照片、公开联系资料、日期、附件、关联身份；名称/摘要进卡片，细节进正文，不增加新卡片字段布局 |
| 教师 | 稳定身份、姓名、经审定的完整介绍、发布状态、人工顺序、详情地址 | 职称、照片、摘要、研究领域、公开联系方式、分节正文、人才类别与年份、首页推荐；未提供的信息不编造 |
| 轮播 | 稳定身份、已获准图片、有效替代说明、顺序、启用及发布状态 | 主标题、英文眉题、介绍、图注；是否必须有标题按正式素材确认，不能保留“待提供”当正式宣传 |
| 附件 | 平台文件、名称、可访问 URL、文件类型和访问权限 | 文件大小、排序；平台自动产生的属性无需人工重填 |
| 友情链接 | 名称、有效 URL、校内/校外组、顺序、启用状态 | 不增加无需展示的业务字段 |

正文至少支持段落、小标题、列表、图片与图注、链接及附件。旧预览使用结构化文本，不代表博达必须使用同样的输入方式；若博达使用富文本，应保留正文语义并清理不受信任的脚本和样式，避免破坏全站设计。不要要求编辑员填写 CSS、DOM 选择器或前端文件路径。

图片保持当前图框比例和裁切方式；二维码需完整、清晰可扫描，教师照片需预览人脸裁切。文案长度没有已确认的统一字符硬限制，不能凭空规定“超过 N 字就不能保存”；列表摘要按原样式截断，详情保留全文。固定展示标题若以后确需改字，由前端复核自托管字体子集覆盖。

## 6. 共用、排序、空态与发布规则

1. **只读公开版本。** 草稿和预览不进入公开首页、列表、详情；编辑已发布内容时，未发布的新版本不覆盖线上旧版本。发布与撤下需同步更新引用页和平台缓存。
2. **不复制资料。** 新闻、教师、科研条目在概览和详情间以稳定身份引用；可分别设置首页推荐顺序与栏目内部顺序。独立首页介绍、轮播是配置内容，不是重复的业务文章。
3. **排序保留依据。** 新闻通知默认发布日期倒序；普通集合当前按人工顺序、日期倒序、稳定 ID；制度以发布日期倒序优先。教师规则见第 4.4 节。首页推荐优先规则是第 3 节建议默认，接入时落实，不宣称已经实现。
4. **数量与分页。** 首页 4 条新闻、3 条通知、3 位教师；概览集合最多 3 条，摘要最多 3 行。完整列表须能访问全部已发布记录并支持分页；旧 Django 每页 10 条仅作为参考，博达分页数量和控件需模板联调确认。
5. **空态不伪装成数据。** 无内容时保留现有栏目用途说明及“相关内容正在整理中”；人才分类、二维码按各自例外规则。空态文案是模板配置，不录成文章。正式站不能回填 `【演示】` 新闻、假成员或未审定素材。
6. **明确清空和停用。** 清空可选图片/联系方式、停用轮播/友链应真正生效，不悄悄恢复默认业务内容。旧 Django 部分空值回退行为不是正式平台目标。
7. **撤下全链路。** 撤下记录从首页、概览、分类、列表和搜索引用中移除，直接详情地址不得继续提供正文；返回平台统一不可用/404 页面。图片附件的旧公开 URL 能否一并失效需核实平台缓存和权限，不以隐藏下载链接代替文件撤回。
8. **工作流用学校配置。** 必须有保存草稿、预览、发布、撤下等操作结果；审核人数、角色和权限由学校确认。文档不假定所有内容已有双人审核。

## 7. 兼容与不需要单独后台化的部分

| 部分 | 实施处理 |
|---|---|
| 所有列表项对应的详情页 | 同类共用详情模板，不为每一篇文章建一套模板；教师详情可独立模板 |
| 本地 `content-<id>.html`、Django `entry-*`/`record-*` | 仅表示现有预览地址习惯；博达用真实生成 URL 并建立映射，不要求沿用数据库 key |
| `layout-*` 页面 | 历史版式兼容页，不是新的业务栏目，不录独立内容 |
| `news-preview-*`、`notice-preview-*`、`content-demo-media-*` | 静态审核演示详情，不当作正式资料源导入；正式平台显示真实发布文章 |
| `frontend/review.html`、`frontend/examples` | 开发审核入口和样例，不作为正式公开业务页面 |
| 芯片横幅、装饰字、过渡、下划线、小箭头、404 表情、源码署名彩蛋 | 保留现有设计，不做普通编辑员的后台配置；模板迁移不能丢失 |

本表的 `key` 来自前端栏目注册与旧预览适配，只用于准确定位，不是博达编号。旧 URL、锚点及别名是否可保留或重定向须记录映射；不能通过复制文章保留旧地址。

## 9. 学长实施顺序与交接验收

先配置公共头尾和站点资料，再跑通一条新闻的完整闭环；复用到通知、一般文章集合，随后完成单篇介绍、教师/机构/科研等资料、首页推荐、轮播及文件。可以分批实施，但本次交付范围是全站业务内容，不只新闻通知。

| 验收操作 | 需要看到的结果 |
|---|---|
| 新增新闻，先存草稿再预览 | 预览能看，公开首页/列表/直接详情均看不到草稿 |
| 发布新闻并推荐、调整推荐顺序 | 首页与列表详情一致，封面与文字对应，数量正确 |
| 修改已发布正文但先不发布 | 线上仍是旧版，预览是新稿；发布后所有引用更新 |
| 撤下被首页引用的文章 | 首页/概览/列表/搜索不再出现，直接链接不泄露正文；已接入搜索时同步核对 |
| 修改教师照片、职称与多个称号年份 | 首页、完整名录、人才分类、详情一致；同一教师首页不重复 |
| 为各集合各发布一条记录 | 概览、列表、详情对应正确；超过概览上限后仍能从完整列表看到全部 |
| 给一个方向关联课题组 | 同一课题组资料被正确引用，修改后无需重复录入 |
| 轮播换图、换序、停用，含全部停用 | 内容按配置显示，计数正确，停用项不回填 |
| 修改联系方式、二维码及友链 | 联系页和公共页脚同步；无图/停用规则正确，二维码能扫描 |
| 上传并替换图片、PDF，清空可选图片 | 手机/桌面可看，附件可用，替换生效，清空不回填未审定素材 |
| 无数据、长标题、长正文、缺图、多页列表 | 保留现有空态和响应式，详情不截断，导航和链接有效 |

每个表格位置记录：博达栏目/资料源标识、绑定模板、正式 URL、实施人、验收日期、结果及证据。以下事项须学长或学校回填：真实字段/组件标签、推荐排序机制、多称号与科研关联实现、上传限制、审核角色、分页、缓存刷新、旧地址兼容、附件撤回方式。记录“待确认”即可，不能用猜测的编号填满表格。

实际完成状态继续统一维护在 [STATUS.md](../STATUS.md)。本文只规定范围和验收标准；本轮未配置博达、未修改业务数据、未验证正式平台发布链路。
