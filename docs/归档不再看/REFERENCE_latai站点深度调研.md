# latai.henu.edu.cn 站点深度调研

> 调研对象：https://latai.henu.edu.cn/
> 调研时间：2026-10-12
> 调研方式：curl 抓源码 + 响应头/资源/路径探测 + 与 lab.henu.edu.cn 对照
> 结论先行：**这是全校站群里最特殊的一个子站——底层仍是博达 VSB（同源 IP/系统资源/组件注释），但前台是一套手工开发的现代设计站（Node 构建脚本产出静态 HTML + 完整中英 i18n），新闻/通知列表才回接博达 CMS 组件。它证明了「站群上可以跑自定义前端」，对 ic.henu.edu.cn 是直接可抄的先例。**

## 3. 后端 / CMS：博达 VSB 底座仍在，但只留「内容岛」

VSB 证据（首页源码实测）：

- `<meta name="pageType" content="1">`、`pageTitle` —— VSB 页面元标
- `index.vsb.css`、`_sitegray/_sitegray.js`（全站变灰）、`/system/resource/js/vsbscreen.min.js`、`/system/resource/js/counter.js` —— VSB 系统资源照常加载
- `site-shell.js` 中页面级配置：`footerCmsComment: "<!-- 博达组件区域结束：新闻列表（模板三） -->"`（news.html）、`"<!-- 博达组件区域结束：通知列表（模板四） -->"`（notices.html）——**新闻/通知两个动态列表是博达 CMS 组件直出的「内容岛」，嵌在自制外壳里**
- 站内信息类 URL 不存在：本站所有页面都是 `*.html` 语义化命名；首页出现的 `info/xxxx.htm` 全部是**外链**到 news.henu.edu.cn / gxb.henu.edu.cn 的校新闻稿（本站 `info/1051/1935.htm` 直接 404）

**架构推断**：开发者用 `scripts/build-site.js`（见 `site-shell.js` 首行注释：`Generated by scripts/build-site.js. Edit src/templates/partials/ or src/data/site.js.`）从 `src/templates/` + `src/data/site.js` 静态生成全站 HTML，再整体发布到 VSB 站点空间；其中 news/notices 列表页在构建时预留了博达组件占位符（`footerCmsComment` 字段），由 CMS 发布时注入动态列表。——**即「自定义前端壳 + VSB 内容组件」的混合架构**，不是标准 VSB 可视化模板产出。

### 与 lab 站后台模式对比

| | lab（纳米学院） | latai（低空学院） |
|---|---|---|
| 页面产出 | VSB 可视化组件编辑直出 | 本地构建脚本产出，整页上传/发布 |
| 文章 URL | `info/<栏目>/<id>.htm` | `news-xxx.html` 语义化静态页 |

| 维护方式 | 后台编辑 | **改 src/ → build → 发布**（工程化流程，需要会写代码的人） |

## 4. 前端技术栈（全新手写，非 VSB 模板）

| 层 | 内容 |
|---|---|
| 构建 | Node 静态生成器 `scripts/build-site.js`（`src/templates/partials/` + `src/data/site.js` → 全站 HTML） |
| 运行时 JS | `js/site-shell.js`（42KB：全站页面配置表 `pages{}` + header/footer 模板字符串 + `{{mustache}}` 占位渲染 + 注入 DOM）；`js/main.js`（9KB：语言切换、header 高度同步等交互）——**零框架，无 jQuery、无 Vue、无构建产物 hash** |
| i18n | `data-lang-zh`/`data-lang-en` 成对 span + `localStorage('site-lang')` + `<html lang>` 切换；placeholder 双语 data 属性 |
| CSS | `css/style.css` **288KB 单文件**，CSS 变量设计令牌：`--navy #0a0f1c / --univ-blue #0b32ac / --garnet #7a1623 / --gold #b8902b / --ember #e2590c / --ink/--paper/--radius-*/--shadow-*`；`--maxw: 1240–1320px` |
| 图标 | 内联 SVG（stroke 风格，search/phone/mail/pin 等 icon path 写在配置里）——不再是 PNG 切图 |
| 媒体 | `assets/*.jpg/png` + **hero 视频 `assets/rocket-launch-hero.mp4`**（火箭发射，全站首屏视频背景） |
| 无障碍 | aria-label、aria-expanded、`#main` skip link、语义化 header/nav/footer——明显受过现代前端训练 |
| 响应式 | 单一 style.css 内 media query + `nav-toggle` 汉堡菜单；仍加载 vsbscreen（VSB 强制注入，实际冗余） |

## 5. 字体（重点发现：设计意图 ≠ 实际渲染）

HTML `<head>` 加载 Google Fonts：

```html
<link href="https://fonts.googleapis.com/css2?family=Ma+Shan+Zheng&family=
Noto+Sans+SC:wght@400;500;700;900&family=Inter:wght@400;500;600;700;800&display=swap">
```

设计意图三层字体：

| 令牌 | 字体 | 用途 |
|---|---|---|
| `--ff-brush` | **Ma Shan Zheng 马善政毛笔体** | 标题书法字（cursive 兜底） |
| `--ff-display` | **Noto Sans SC / 思源黑体** | 中文正文（-apple-system 兜底） |
| `--ff-eyebrow` | **Inter** | 英文小标/数字 |

**但实际被本站自己的 CSP 拦截**：响应头 `Content-Security-Policy` 白名单只有 `'self' *.henu.edu.cn *.bcebos.com *.conac.cn *.eol.cn *.staticfile.net *.edu.cn *.baidu.com *.qq.com *.kaipuyun.cn` 等——**fonts.googleapis.com / fonts.gstatic.com 均不在列**。浏览器会拒绝加载该样式表（console 报 CSP violation），真实渲染全部回落到系统字体（sans-serif / -apple-system）。书法体效果只有开发者本地或 CSP 放行的环境才看得到。

→ 典型「站群统一 CSP 与自定义前端冲突」案例：设计稿想要的 webfont 需要向校网管申请把 `fonts.googleapis.com fonts.gstatic.com` 加进 CSP，或把字体文件自托管到 `assets/`（`default-src 'self'` 允许本站字体，这是绕开 CSP 的合规路径）。

## 6. 功能缺口（实测）

- **站内搜索是摆设**：模板里 `<form ... action="#" onsubmit="return false;">`，main.js 只更新 placeholder，无提交逻辑——全站 35 页无法被检索（lab 站至少有博达智能搜索 `/aop_views/`）
- **无备案悬挂**、无 robots.txt（超时未取到，大概率无）、无 sitemap
- `/system/` 404——后台管理入口在此子站不暴露（编辑流程可能在站群主控侧完成）

## 7. 对 ic.henu.edu.cn 的启示（重要）

1. **先例已开**：latai 证明校站群允许子站上传**自构建静态前端**——不必接受 VSB 老模板。ic 学院站同样可走「本地工程化开发 → build → 发布到站群」路线，内容与外观兼得：新闻/通知用博达组件自动更新，其余页面手写。
2. **代价**：需要有人会 `build-site.js` 这类流程（模板引擎 + 数据文件），且每次改页面要重新构建发布——比纯后台编辑门槛高。latai 这套显然是学生/开发者作品（设计令牌、i18n、aria、SVG icon、视频 hero 全是现代手法），不是蓝创科技模板。
3. **要避的坑**（latai 已踩）：
   - webfont 必须自托管或申请 CSP 放行，否则只对自己可见；
   - 搜索框要做成真的（可回接 `/aop_views/search/` 博达搜索，lab 站已验证该端点同源可用）；
   - 页脚记得挂备案号（latai、lab 都没挂，ic 站应合规一点）；
   - HTTP→HTTPS 跳转是全站群级问题，可向信息办提。
4. **栏目设计参考**：latai 的栏目（科学与创新/人才培养/师资队伍/公共服务/关于/联系/招聘 CTA）比 lab 的传统八栏目更现代精简，megamenu + 锚点长页的模式适合新学院「内容少但要好看」的阶段；ic 学院内容多时可折中。
5. **技术栈暗示**：`site-shell.js` 的注释结构（`src/data/site.js` 单数据源、per-page 配置表、mustache 占位）——如果 ic 站走自建前端，这个轻量架构本身就可直接复用思路：一个数据文件 + 模板 partials + 构建脚本，比上 React/Vue 重框架更符合「简单优先」决策。
