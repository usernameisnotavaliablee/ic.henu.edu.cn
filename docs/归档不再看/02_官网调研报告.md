## 二、与本项目直接有关的已核实事实

### 1. 筹建名称有官方报道依据

工学部[《我校召开新工科建设启动会》](https://gxb.henu.edu.cn/info/1051/1925.htm)发布于2025年12月16日，列出的九个拟建学院包含“集成电路与微纳电子”。

可用于说明筹建背景；本轮用户已确认中文名为“河南大学集成电路与微纳电子学院”，不再重复询问中文名；英文名和成立、揭牌事实仍不能从历史报道直接推定。

[2026年5月首批新工科学院成立报道](https://news.henu.edu.cn/info/1083/193197.htm)列出的首批单位是新能源与智能制造、低空技术与空天信息、合成生物与制药工程。该报道不能直接作为本学院已经成立的依据。

### 2. 校内存在可追查的师资与课程资料

[物理与电子学院在职教师页面](https://phye.henu.edu.cn/szdw/zzjs.htm)列有“集成电路科学与工程系”；[专业介绍页面](https://phye.henu.edu.cn/bkspy/zyjs.htm)含专业介绍和不同版本的培养方案。

它们可用于对照教师履历和查找资料来源，但不能把原学院的全体人员、专业、培养方案直接归到新学院。首版3名教师以老师确认的名单为准。

### 3. 学校提供网站群及独立服务器相关申请

[网站群管理指南](https://net.henu.edu.cn/info/1060/4978.htm)公开了后台入口、管理员使用手册和联系渠道；[信息化部门官网](https://net.henu.edu.cn/)列有“站群站点申请”“域名申请”“虚拟服务器申请”。

在47个河大院系入口返回的页面中，43个页面可见 Visual SiteBuilder 生成标记。这是平台使用线索，不代表我们已核实这些站点的后台权限、数据库或维护方式。

当前决定：正式发布采用学校博达站群；Django + SQLite仅作开发预览和测试。学校子站账号、模板与组件权限尚待交接。

校方另有[信息系统集成标准规范](https://net.henu.edu.cn/info/1060/3555.htm)。它涉及业务系统集成；本项目适用哪些要求应由校方确认，不能未经确认把全部条款搬进学院展示网站需求。

## 六、对开发设计的结论

1. 学长工程已核实存在博达组件适配；正式走学校站群，预览工具保持独立。最新工程结论见第八节。
2. 栏目、页面、内容和功能分开记录。例如“师资队伍”是栏目，“教师详情”是页面，简历是内容，筛选是功能。
3. 素材清单应随首版确认结果分期。他校常见栏目不能直接转换成上线硬性条件。
4. 把教师、研究方向和课程材料整理成结构清晰的条目。便于复用模板，后续也便于维护。
5. 复用前逐项核实真实功能。搜索框、双语按钮、预约链接、后台入口都不能只凭外观算作已完成。
6. 公开报道是核实线索，不是自动获准发布的学院材料。正式名称、师资归属和新学院办学情况由学院审定。

## 七、接下来如何完成调研

按已确认的范围继续：河大主站、学院、新闻、专题、官媒；39所985中实际相关院系。每站补齐主要栏目、代表性内页、内容组织、真实功能和桌面/手机呈现，并保存对应证据。

访问受限的页面保留状态，不以“打不开”认定站点失效、域名空闲或没有相关学院。搜索引擎访问也有受限情况，因此本轮不声称已找到全网所有相关公开资料。

后续发现进入候选清单；在15号MVP范围确认后，新增建议不自动加入首版。


## 八、本轮基础开发必做：调研提取与最新源码复核

更新：2026-10-11。已对照《河大各学院官网调研》、本报告与《调研附件_站点核查台账》，并读取低空参考包中的导航、头部、构建、组件和部署资料。本节为当前实施摘要；历史样本频率只作取舍参考，不等于学校规定。没有在本轮重新扫描全部学校网站，也没有登录学校后台。

### 1. 后台有接入参考，但不是现成HTTP接口

公开《网站群管理指南》记录学校统一后台；没有学院前台的登录入口，并不能证明学院不存在其他内部系统。后台入口、可用账号与IC子站权限仍以学校实际交接为准，不对历史HTTP地址提交密码。

| 问题 | 当前证据 | 本轮做法 |
|---|---|---|
| 新闻怎样进入前台 | 低空 scripts/build-boda-site.js 生成JSP模板及 home-news、home-notices、news-list、notice-list 插槽 | 制作IC页面结构和插槽，取得站群账号后绑定新闻/通知资料源 |
| 字段怎样接 | BODA_CMS_COMPONENT_TEMPLATES.md 有 list_news、showTitle、showDate、showAbstract、url、picUrl 和分页 | 建立字段对照，绑定的是学校模板组件，不猜写 /api/news |
| 详情页怎样接 | article-detail.html 使用 content 与 vsb_contentid，含来源、日期、正文、附件与上下篇 | 共用详情样式，按学校组件语法和输出安全规则验证 |
| 有没有可直接复用的学校REST或SSO实现 | 已检查工程中未找到此类实现；本地编辑器只是回环地址上的静态文件工具 | 不编造接口，也不将本地编辑器当正式后台 |
| 还缺什么 | IC子站、栏目/资料源/组件编号、模板权限、后台入口与账号 | 用空配置占位；这些是学校接入资料，不是需要重新自研的CMS |

最简单的流程：老师登录学校后台 → 编辑审核新闻 → 站群组件生成页面 → 访问者浏览IC官网。我们做前台模板和组件适配，不需要从浏览器向未知学校接口拉新闻。

### 2. 统一身份认证：本轮不写

学院展示前台没有学生登录需求；老师在学校已有后台登录。学校后台是否已经接入CAS/OAuth尚未核实，但无论采用哪种登录方式，都不需要在学院前台复制学校认证。自有演示后台使用独立测试账号，不使用或代收学校密码。

只有后续新增预约、选课、个人业务办理等真正需要身份信息的业务时，才另行申请学校认证接入参数、回调地址和权限。本轮不加入此类业务系统。

### 3. 站内搜索：建议留位，正式优先复用站群

低空 src/templates/partials/header.html 第10行的搜索表单 action 为 #、onsubmit 返回 false；源码中该界面不能作为已经实现搜索的依据。其他学院出现的搜索组件地址只能说明存在平台能力，不能把它们的站点ID或搜索范围直接套给IC。

| 方案 | 相对难度与依赖 | 建议 |
|---|---|---|
| 学校站群搜索组件 | 低到中；需IC站点/资料源、结果页组件、权限与索引配置，等待时间无法由我们保证 | 正式版首选；需验证查询限定在IC站内 |
| 自有预览的标题/摘要/教师姓名查询 | 低到中；已具备Django内容模型后实现，查询只能包含批准内容，需空结果与分页 | 今晚可选增强，不冒充学校全文搜索 |
| 自建全文、分词、PDF检索与跨站抓取 | 中到高；增加索引、同步、权限和维护工作 | 本轮不做 |

设计预留搜索入口和结果页版式。学校组件没接通时，内部预览标注待接入或隐藏入口；不提供可输入但无响应的假搜索。公开版搜索要么可用，要么先隐藏。是否今晚必须实现预览搜索，是尚可由用户选择的范围项；建议优先保首页、手机和内容闭环。

### 7. 手机适配从设计起步

设计时同时规定桌面/手机排版；实现每个组件时同步写响应式样式；每阶段结束进行浏览器尺寸检查，交付前再做真实手机浏览器检查，不能到最后才统一修缮。

验收宽度至少320、375/390、768、1024、1440像素。主内容不横向溢出；长标题、导航、教师照片和正文图片可适配；菜单可关闭，点击区尽量不少于44像素；保留浏览器缩放，不使用user-scalable=no；新闻详情中的宽表格在独立容器横向滚动。芯片动效不阻挡正文，减少动态效果时静态显示。

“有viewport”“加载vsbscreen.min.js”只能视为布局线索，不能替代以上检查。学校模板发布后还要在实际域名复测，以发现平台注入脚本和正文内容带来的差异。
