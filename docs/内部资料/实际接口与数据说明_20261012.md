# 实际接口与数据说明

补充核查：当前是已实现的 Django 后台表单与前台读取路由，没有公共 REST 写入 API；“所有占位后台可改”尚未全部实现。详见 [可维护范围与明确缺口](队友统一交付与后台可维护范围_20261012.md)，含首页硬编码文案/配图、教师空位以及轮播关闭后回退默认内容的问题。

依据 2026-10-12 工作区（运行代码 15e8dac，最新回执 73dce92）核对 backend/config/urls.py、content/views.py、models.py、services.py、entry_admin.py 与构建目录。这里的接口主要是服务端 HTML 路由及 Django 后台表单，不是对外 REST API。

## 1. 前台路由

| 路由 | 数据/结果 | 说明 |
|---|---|---|
| /、/index.html | Publication + 教师发布资料 + 内容插槽 | 首页前 4 条新闻、前 3 条通知 |
| /news.html、/notices.html | Publication 按类别 | 每页 10 条，GET ?page= 页码，使用 Paginator.get_page 容错 |
| /<news或notice标识>.html | 已批准 Publication | 未批准、撤下或不存在为 404 |
| /<集合slug>.html | 已发布集合条目 | 卡片每页 9 条，列表每页 10 条 |
| /entry-<标识>.html | 新建 ContentEntry 已发布快照 | 必须属于有效集合且可见 |
| /record-<旧位置转换标识>.html | 兼容旧固定区块的集合详情 | 例 record-admissions-section-3.html，不改原业务数据 |
| /faculty.html、/teacher-<标识>.html | 默认教师资料合并发布快照 | 明确撤下的教师不恢复默认详情 |
| /contact.html | site_info | 站点发布资料合并构建默认值 |
| /about.html 等白名单页 | generated 外框 + 内容插槽 | 白名单由 views.STATIC_PAGES 限定，不任意读取 HTML 文件 |
| /assets/<文件>、/css/<文件>、/js/<文件> | preview 下允许的单层文件 | 文件名字符和扩展名有限制，缓存 300 秒 |
| /healthz | JSON | {status: ok, mode: public-readonly 或 local-preview}，会触发数据库查询 |
| /robots.txt | 文本 | 禁止索引；不是访问控制 |

以上前台视图使用 require_safe（GET/HEAD）。PUBLIC_ONLY 中间件拒绝后台路径和非 GET/HEAD/OPTIONS 写请求；中间件直接拒绝时返回 404，视图方法限制通常返回 405。公网代理也可能返回 405，不应将所有层的拒绝码写成同一个值。

静态 layout-*.html 只用于版式预览，不是服务端业务详情路由；不能用它证明动态发布数据正常。

## 2. 后台路由与表单

| 入口 | 用途 |
|---|---|
| /preview-admin/、login/ | Django 后台与会话登录 |
| /preview-admin/content/article/ | 新闻通知草稿列表 |
| article/add/、article/<id>/change/ | 新增/编辑，隐藏 expected_revision 与 submit_for_review 控制版本及提交 |
| article/<id>/review/ | GET 核对草稿，POST decision=approve/return/withdraw + expected_revision + CSRF token |
| /preview-admin/content/publication/ | 已批准快照，只读 |
| /preview-admin/content/auditevent/ | 新闻操作记录，只读 |
| /preview-admin/content/contententry/ | 教师、栏目、轮播、站点资料列表及发布动作 |
| contententry/add/、contententry/<id>/change/ | 保存草稿；key 创建后只读 |

表格中的相对入口均位于 /preview-admin/content/。ContentEntry 发布通过列表 action=publish_selected（Django 原生选中项和 CSRF），不是独立公共发布 API。不建议脚本直灌；当前演示内容录入要求通过后台 UI。

私有管理实例必须是直接回环/SSH 隧道来源，staff 登录仍需相应权限。新闻审核需要 content.review_article；资料发布需要 content.publish_contententry。Article 管理禁删除；ContentEntry 管理同样禁删除。多角色人工验证和权限设计进一步完善交队友。

## 3. 模型与状态

| 模型 | 关键字段 | 作用 |
|---|---|---|
| Article | slug、category、title、summary、body、source、date、image、image_alt、is_placeholder、state、revision、updated_by/at | 新闻通知草稿；category 为 news/notice |
| Publication | 上述内容字段、article 一对一、revision、approved_by/at | 前台批准快照，Article 被保护关联 |
| AuditEvent | article、actor、action、revision、occurred_at | 草稿保存、提交、批准、退回和撤下记录 |
| ContentEntry | key、collection、direction、title/subtitle、summary/body、image、source、date、sort_order、is_visible、站点字段、published JSON | 所有非新闻类资料的草稿与发布快照 |
| Django 内置 | User、Group、Permission、会话及后台日志 | 登录、角色与后台操作日志 |

Article 内容限制：标题 160、摘要 400、正文 30000 字符；ContentEntry 摘要 3000、正文 30000。图片不存二进制，不接受任意 HTML 执行。

新闻事务流程：save_draft 检查新增/修改权限并校验旧 revision；提交后 state=submitted。approve 必须处于 submitted，复制内容到 Publication；return 保留旧 Publication；withdraw 删除 Publication、保留草稿。编辑与审核均推进 revision，旧窗口应重开。公开页面只读取 Publication。

ContentEntry 保存不覆盖 published；发布动作事务内 full_clean 后复制 snapshot()；is_visible=false 也必须发布才生效。它没有 Article 的独立 submitted/revision 工作流；并发覆盖和多人审核能力不能照搬新闻的结论。site_context 对非空值合并默认配置；教师默认资料也会被已发布 key 覆盖。

显示端并非统一隐藏：集合条目和教师按 is_visible 排除；固定概况区保留区块并显示待更新；轮播 is_visible=false 回退默认内容而非移除轮播；site 不可见时回退默认站点配置。因此“发布撤下设置”不能笼统等同于所有类型均从页面删除。

纯文本规则由 content_slots.content_paragraphs 和 site/plain_text_body.html 共用：CRLF 转 LF，空行切段，段落以 `## ` 开头标为标题，其他段落保留换行；不支持任意 Markdown。小标题必须独占一段，否则同一段其余文字也会被视为标题内容。

## 4. 21 个集合映射

概览文件为“页面前缀.html”；集合 URL 为“页面前缀-section-N.html”；key 为“页面前缀.section-N”。准确目录由 frontend/src/data/collections.js 生成到 backend/content-catalog.json。

| 页面前缀 | N：栏目（布局） |
|---|---|
| science-innovation | 1：研究方向（cards）；2：研究进展（list）；3：学术交流（list） |
| research-platforms | 1：研究平台（cards） |
| research-groups | 1：课题组（cards） |
| regulations | 1：规章制度（list）；2：办事流程（list） |
| party-building | 1：党建动态（list）；2：学习园地（list） |
| admissions | 1：本科生招生（list）；2：研究生招生（list）；3：就业指导（list） |
| community | 1：师生活动（list）；2：学生风采（cards） |
| ic-world | 1：学科科普（list）；2：芯片与微纳世界（cards） |
| media | 1：媒体报道（list） |
| talent-cultivation | 1：学科与专业（cards）；2：课程与培养方案（list） |
| public-service | 1：服务指南（list） |
| careers | 1：人才招聘信息（list） |

集合概览展示前 3 条。条目按 sort_order 升序、日期降序、key 稳定顺序排列，只使用已发布快照。平台和课题组旧 section-2 通过 legacyKeys 合并到对应 section-1 集合；旧正文可兼容成 record- 详情。

新增 key=entry-* 必須选择有效 collection；direction 仅供课题组集合关联已发布、可见的研究方向。已撤下的方向在后台提示重新调整关联，不自动创造方向或修改团队内容。

其他 key：about.section-1/2/3 固定概况区块，teacher-* 教师，home.slide-1…6 轮播，site 站点资料。其余固定位置由 content-catalog.json 的 slots 记录；该文件不是业务库。

## 5. 迁移、配置与资源

| 迁移 | 作用 |
|---|---|
| 0001_initial | Article、Publication、AuditEvent |
| 0002_contententry | ContentEntry 与发布权限 |
| 0003_contententry_collections | 所属集合及研究方向关联 |
| 0004_article_image_options | 新闻/发布快照图片选项 |
| 0005_article_body_heading_help | 正文字段说明；SQLite SQL 为两个 no-op |

关键环境变量：IC_DATA_DIR、IC_SECRET_KEY（可由 DATA_DIR/secret.key 读取）、IC_ALLOWED_HOSTS、IC_PUBLIC_ONLY、IC_HTTPS、IC_PORT。真实值不入库。serve.py 始终绑定 127.0.0.1；公网 HTTPS 场景下才配置相应协议代理头信任，当前 HTTP 部署不要套用占位 HTTPS 模板。

源/生成边界：构建写 preview、generated、content-catalog.json、seed-content.json；不会写业务库。catalog 在进程内缓存，更改后部署重启服务，不能期待运行中自动热更新。
