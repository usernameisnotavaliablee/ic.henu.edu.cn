日期：2026-10-12。执行：Claude Code。**本轮回执只涉及本机代理，未改动学院网站任何代码、未部署、未提交或推送。**

## 1. 结论

**已修复。** 本机浏览器（继承系统代理）现在可以正常打开 **https://hdwzgzs.cn/**：
最终地址 `https://hdwzgzs.cn/studio#Prologue`、**HTTP 200**、标题「河南大学网站工作室 | HENU Web Studio」、
49 个资源全部加载成功、45 张图片全部加载。

根因**不是**站点、DNS 或 TLS 校验，而是本机 **Clash Verge 的 DNS 配置**。

## 2. 排查过程与证据

### 2.1 代理软件识别

| 项 | 值 |
|---|---|
| 软件 | **Clash Verge**（`clash-verge.exe`，`E:\Software\Clash Verge\`） |
| 核心 | `verge-mihomo.exe`，监听 `127.0.0.1:7897`（混合端口）与 `0.0.0.0:53`（DNS） |
| 服务 | Windows 服务 `clash_verge_service`（Running / Automatic） |
| 配置目录 | `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev` |
| 当前订阅 | `程芷嘉-500G`（remote 类型）；另有多个订阅，未改动 |
| 系统代理 | 已启用：`ProxyEnable=0x1`、`ProxyServer=127.0.0.1:7897` |

### 2.2 现象与逐步定位

| 测试 | 结果 | 说明 |
|---|---|---|
| DNS 解析 | 正常，返回 Cloudflare 地址（含 IPv6） | 排除 DNS 污染/解析失败 |
| curl **直连** `https://hdwzgzs.cn/` | 301 → `/studio` → **200** | 排除站点故障 |
| curl **经代理** | TLS 握手失败 / 偶发超时 | 复现问题 |
| hosts 文件 | 无该域名 | 排除 hosts |
| 规则命中 | 仅一条：`DOMAIN-SUFFIX,cn,DIRECT` → **DIRECT** | 路由本身是直连，**不是路由问题** |
| 经代理访问 `www.henu.edu.cn`（同为 .cn、同为 DIRECT） | 200 | 排除"所有 DIRECT 都坏" |
| 经代理访问 `www.cloudflare-cn.com`（同为 Cloudflare） | 200 | 排除"Cloudflare 被墙" |
| **curl -v 经代理** | `CONNECT` 得到 **200 Connection established**，随后 **TLS 无任何响应** | 说明 mihomo 接受了隧道，但它自己到上游的**直连没连上** |

### 2.3 根因

关键证据链：

1. 向 **mihomo 自己的 DNS（127.0.0.1:53）** 查询，返回的是 **fake-ip**（`198.18.0.6`）——
   说明经代理的请求由 mihomo 自行解析，**不使用系统 DNS**（系统 DNS 是 `10.82.82.192`）。
2. 订阅自带的 DNS 配置为：
   ```yaml
   nameserver: [8.8.8.8, https://doh.pub/dns-query, https://dns.alidns.com/dns-query]
   fallback:   [https://doh.dns.sb/dns-query, https://dns.cloudflare.com/dns-query,
                https://dns.twnic.tw/dns-query, tls://8.8.4.4:853]
   fallback-filter: { geoip: true, geoip-code: CN, ... }
   ```
3. 实测这三个 fallback 服务器**在国内不经代理全部不可达**：
   `doh.dns.sb` 连接失败、`dns.cloudflare.com` 超时、`dns.twnic.tw` 超时。
4. `fallback-filter` 的 `geoip-code: CN` 语义是：**主 nameserver 返回非 CN 的 IP 时，必须改用 fallback 的结果**。
   `hdwzgzs.cn` 托管在 **Cloudflare（非 CN）** → 需要 fallback → **fallback 全部不可达** → 拿不到可用地址 →
   mihomo 的 DIRECT 连接失败。
5. `www.henu.edu.cn` 解析到 **CN IP** → 直接采用主 nameserver 的结果，不需要 fallback → 正常。

这解释了全部现象：直连正常（用系统 DNS）、经代理失败（用 mihomo DNS）、同类 .cn 域名有的正常有的不正常、
失败表现为握手无响应或超时（fallback 超时）、平板正常（不同网络/未走该代理）。

## 3. 修改位置与内容

**修改文件（持久化的用户 DNS 覆写，订阅更新不会覆盖）**

`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\dns_config.yaml`

**改动**：把原本为空的 `nameserver-policy` 填上**该域名一条**（最小范围，未改全局 DNS、未改 fallback 列表）：

```yaml
  nameserver-policy:
    # 该域名托管在 Cloudflare（非 CN IP），而订阅自带的 fallback DNS 在国内不可达，
    # 导致 mihomo 拿不到可用地址、其 DIRECT 连接失败。这里指定可达的解析器。
    '+.hdwzgzs.cn':
    - 223.5.5.5
    - 119.29.29.29
    - https://doh.pub/dns-query
```

- `+.hdwzgzs.cn` 同时匹配该域名与其子域（如 `erp.hdwzgzs.cn`）。
- 三个解析器均已实测可达且能正确解析该域名（返回真实的 Cloudflare 地址 `104.21.62.209` / `172.67.139.66`）。
- **未**改动订阅自带的 `fallback` 列表、**未**全局关闭代理、**未**改 DNS 服务器设置、
  **未**改 hosts、**未**关闭 TLS 校验、**未**安装任何证书。
- 该文件由 Clash Verge 的「DNS 覆写设置」管理（`verge.yaml` 中 `enable_dns_settings: true`），
  是用户自有配置，**不会被订阅更新覆盖**；未直接编辑生成的运行文件 `clash-verge.yaml`。
