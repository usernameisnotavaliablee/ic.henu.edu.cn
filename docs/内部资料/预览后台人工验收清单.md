# 预览后台人工验收清单

> 此表保留为私有部署阶段记录。2026-10-12 公网已由 Claude Code 部署，最新操作与状态见[公网与多设备人工核验清单](公网与多设备人工核验清单.md)。下方“手机待安排入口”“首页断言未修复”等已被后续回执更新，不再作为当前结论。

更新：2026-10-12。对象：服务器上的 Django＋SQLite 开发预览站，通过 SSH 隧道访问。本清单不是学校博达发布中心的验收表，也不代表正式官网已交付。

## 已有结果与访问入口

- **用户人工验收通过**：前后台可打开；登录；新建标明“功能测试”的新闻；保存草稿；提交；批准；前台查看。
- **Claude Code 报告通过**：25 项 Django 测试、27 项 HTTP 流程检查、服务重启后数据保留。本轮没有独立重跑这些测试。
- **以下待测项目尚未获得用户人工验收结果**，不能因脚本通过而全部勾选。

| 入口 | 地址 |
|---|---|
| 后台 | http://127.0.0.1:8095/preview-admin/ |
| 前台首页 | http://127.0.0.1:8095/index.html |

## 第一轮：先完成这三项

复用你已经发布的“功能测试”新闻，记下详情地址。不要操作真实内容。前后台各开一个标签页；每次检查前台时刷新页面。

| 编号 | 操作 | 预期结果 | 人工结果 |
|---|---|---|---|
| A1 保存修改但不批准 | 打开该新闻，在标题加“第二版”、正文加一段易识别文字；不勾选“保存后提交审核”，只保存。刷新前台详情、新闻列表和首页。 | 后台保留新草稿；前台仍为原来已批准的标题和正文。未审核修改不能提前出现。 | 待测 |
| A2 再次批准 | 重新打开刚才的草稿，勾选“保存后提交审核”并保存；进入“查看草稿并审核 →”，选择“批准到开发预览”，点击“确认此操作”。刷新前台。 | 原详情地址不变，标题和正文更新；新闻列表同步更新；若进入首页展示名次，首页标题/摘要/图片也应与批准内容一致。 | 待测 |
| A3 撤下 | 在审核页选择“撤下前台预览”，点击“确认此操作”；刷新首页、新闻列表，再打开先前记录的详情地址。 | 首页及列表不再展示；旧详情地址返回找不到内容的 404 页面；后台草稿仍保留。 | 待测 |

首页新闻最多展示 **4 条**，通知最多 **3 条**。排序依次按展示日期、批准时间、记录编号倒序；未进入首页名次不属于故障。需要检查首页联动时，为测试内容填写适当的展示日期，并先确认其在列表中的排名。

目前 HTTP 验收脚本的首页联动项只断言响应为 200，没有强制断言测试标题出现。因此 **A2 的首页内容核对不能省略**。

## 第二轮：第一轮通过后再测

继续使用少量带“功能测试”标记的内容；新建内容保持“示例内容”勾选。正文为纯文本，配图通过下拉选择现有素材，当前没有富文本编辑和图片上传功能。

| 编号 | 操作 | 预期结果 | 人工结果 |
|---|---|---|---|
| B1 撤下后恢复 | 对 A3 的草稿重新提交、批准。 | 原地址恢复访问，列表重新出现；内容为本次批准版本。 | 待测 |
| B2 通知流程 | 新建“功能测试—通知”，栏目选通知，使用未用过的 `notice-` 开头地址标识；保存、提交、批准，最后撤下。 | 未批准前不出现在前台；批准后出现在通知列表及对应详情，符合排名时出现在首页通知区；不混入新闻列表；撤下后消失。 | 待测 |
| B3 显示字段 | 编辑测试新闻，填写摘要、两段以上正文、来源、展示日期；切换配图并填写图片说明，提交、批准。 | 详情的日期、来源、配图、说明和正文分段正确；列表/首页按各自设计展示的标题、摘要或配图与批准版本一致；无乱码或文字遮挡。 | 待测 |
| B4 退回修改 | 对一条已批准测试新闻修改并提交；在审核页选择“退回修改（保留旧预览）”并确认。 | 后台回到可修改状态；前台仍显示此前批准的版本，不能变成新草稿，也不能被撤下。之后可再修改、提交、批准。 | 待测 |
| B5 两个窗口编辑 | 在两个标签页打开同一篇草稿的编辑表单；先在第一个标签页修改并保存，再在第二个旧表单修改并保存。 | 第二次保存出现内容已更新、需重新打开的提示，不覆盖第一次保存。旧表单文字应先复制，再重新打开编辑。 | 待测 |
| B6 常规表单校验 | 尝试保存缺少标题的新草稿；另试使用已有地址标识，以及不符合 `news-` / `notice-` 前缀规则的地址标识。 | 显示清楚的字段错误，不跳到服务器错误页，不保存错误数据。只做常规输入，不开展专项安全测试。 | 待测 |
| B7 后台查找 | 搜索测试内容的标题/摘要；分别使用栏目、状态、示例内容筛选；清除筛选。 | 能找到目标内容；筛选结果正确；清除后恢复相应列表。 | 待测 |
| B8 操作记录与退出 | 查看测试内容的操作记录，核对提交、批准、退回、撤下等已执行动作；退出后台，再访问后台入口。 | 记录能对应实际动作；退出后重新进入后台需登录。当前只验证现有管理员账号，不能据此宣称多角色隔离已人工验收。 | 待测 |

测试结束后撤下本轮测试新闻与通知，避免混入演示内容。撤下保留草稿和日志，当前没有删除操作。已撤下内容若暂不恢复，无需另做处理。

## 后续由开发者安排的检查

以下单独安排，不要求用户为了测试改动整库或安装本机依赖。

| 项目 | 验收内容 | 当前状态/安排 |
|---|---|---|
| 空列表 | 无已批准新闻/通知时，首页和对应列表显示正确空状态。 | 待测；使用隔离测试库，不能撤下现有全部内容来凑空列表。 |
| 分页及排序 | 分类超过 10 条时翻页无重复、遗漏；日期及批准时间排序符合规则；首页取前 4 条新闻/前 3 条通知。 | 待测；在隔离实例生成测试数据。 |
| 多角色操作 | 编辑与审核账号分别走各自允许的流程。 | 待人工验收；现有管理员账号的结果不能代替多角色验收。 |
| 业务库备份恢复 | 备份实际业务库，恢复至隔离位置，核对内容和可启动性。 | 待测；CC 报告的服务重启后数据留存不能代替恢复演练。 |
| 桌面浏览器回归 | 8095 动态站的刷新回首屏、反向滚动打断、锚点、长内容阅读；后台编辑与审核页也检查。 | 待测；用户已确认的轮播/暂停等结果保留，不要求本轮重复全测。 |
| 五种宽度 | 320、390、768、1024、1440 CSS 像素；覆盖首页、新闻/通知列表、长详情、各类静态内页，以及后台登录/列表/编辑/审核页面，检查横向溢出、遮挡、菜单和操作按钮。 | 待测；不能只验首页，当前笼统的排版认可不替代指定尺寸记录。 |
| 手机真机 | 手机浏览器的阅读、菜单、滚动和图片加载；需要使用的后台操作另作检查。 | 待安排可访问入口，不能直接使用电脑隧道的回环地址。 |
| 公网交付 | 确定展示入口、HTTPS及部署验收；学校站群入口与正式发布流程另行对接。 | 当前只有服务器私有部署，不代表公网或学校发布中心已接通。 |
| 专项安全验收 | 按后续部署与学校要求单独执行。 | 按用户安排后置；保留现有防护，不将功能通过写成安全通过。 |

## 反馈格式

先反馈第一轮三项即可，例如：

```text
A1：通过
A2：失败；批准后详情已更新，但刷新新闻列表仍是旧标题。
页面：http://127.0.0.1:8095/news.html
A3：通过
```

发现问题时补充：测试编号、内容标题或地址标识、操作步骤、预期结果、实际结果；必要时附页面截图。不要在记录或截图中包含密码、密钥。

记录“通过”时注明验证来源（用户人工 / Claude Code 脚本 / 本轮独立复验）和日期；尚未执行的一律保持“待测”。
