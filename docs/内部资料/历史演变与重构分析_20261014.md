## 3. 历史上真正没有处理好的地方

### 3.1 扩展了信息结构，却没有建立统一栏目契约

用户要求栏目合并、多级菜单和完整父级面包屑后，我们分别修导航、页面结构、新闻分类和详情。后续新增“概览→列表/卡片→详情”时，又增加集合配置和路由目录。

当前相关定义散布在 `frontend/src/data/site.js`、`collections.js`、构建器的 `crumbs/navigationItems/newsTabs` 与生成的 `content-catalog.json`。生成目录本身不是重复维护；问题是生成前的多个定义和特例需要人工保持一致。

构建器先用旧 href 判定当前项，再由 `collectionHref` 转为列表 URL。此前审查发现：17 个主导航有对应入口的集合列表页，链接存在但当前项未标记。源代码位置：`frontend/scripts/build-site.js:65`。

**根因**：页面身份、栏目身份、导航地址和展示位置没有明确分开。`science-innovation.section-1` 同时承担持久化内容标识和分区序号；未来调序存在误对应风险，但本报告没有发现已经发生的数据丢失。

### 3.2 为快速接后台，采用了对展示文本的精确替换

`serverChrome` 将完整二维码占位 HTML、校训、院名、固定图片路径替换为 Django 表达式，其他固定区块也依赖渲染后的 HTML 匹配。源代码位置：`frontend/scripts/build-site.js:260`。

此前隔离实验只给页脚二维码模板增加换行，构建仍成功，生成外框却失去 `site/wechat.html` 绑定。这属于已经验证的构建契约缺陷。

**根因**：把排版细节当成接口。文案、空白和标签结构是正常会变化的展示实现，不适合承担数据绑定身份。模板渲染后没有核验必要绑定是否成功。

### 3.3 共用了外框，却没有保证内容组件的一致行为

项目已经复用公共头尾、页头控制器、图片反馈和页面过渡。生成出来的 73 份 HTML 不等于 73 份手工维护代码。

实际重复在静态和动态内容组件：静态教师卡经过 `loadingMedia` 包装，`backend/templates/site/teachers.html` 的动态教师卡没有该包装；上一轮 JSON 也记录了行为差异。两种页面可以使用不同模板语言，但输出 DOM 和交互契约应一致。

**根因**：只共享页面外框，没有规定卡片的图片状态、字段、空值和可访问性结构。后来改一条渲染路径，另一条容易遗漏。

### 3.4 动画不断增补，却没有统一状态的决定来源

早期用户多次指出页头瞬移、跨页卡顿。我们补动画时更重视终点和时长，缺少连续操作验收；队友后来加入逐字退场后，原有架构继续累积状态。

当前子菜单同时依赖 `.is-subnav-open`、`aria-expanded`、`inert`、关闭定时器与字符动画。关闭过程中逻辑状态与展示类暂时不一致；再次点击与减少动态效果切换都可能受影响。位置：`frontend/src/js/main.js:138`。

同日已有无头 Edge 155、390×844 证据：关闭后30ms再点仍落到关闭态；关闭后切换减少动态效果再打开，菜单打开但文字 opacity 全为0。这些是特定模拟环境的复现，不等于已在手机真机复现。

**根因**：多个可变状态都能决定“是否打开”，并以估算时间替代完成事件。关闭动画的 `fill: both` 留下终态，减少动态效果路径提前返回，没有统一清理。

### 3.5 功能承诺没有逐项落实为维护能力

用户要求所有待补内容可后台维护，我们增加了 ContentEntry，但首页科研/培养文案与图片、固定教师空位等仍硬编码。轮播关闭是回退默认内容，与真正隐藏不同；站点空值回退也与主动清空不同。

**根因**：将“有后台数据模型”误当成“产品要求已全面覆盖”。当时应该建立“界面位置→字段→编辑入口→发布语义→前台验证”的对应表，并明确保留默认、主动清空、撤下的区别。

这些缺口仍需要记录，但正式方向转向博达后，应先确认平台字段和组件能否覆盖；不宜继续为弥补历史承诺盲目扩建 Django CMS。

### 3.6 交付检查没有覆盖最容易回归的行为

此前审查的73页构建、5629个引用、96项结构检查通过，仍存在上述问题。这说明这些检查能证明文件和链接结构，却不能证明模板绑定完整、连续操作正确或视觉协调。

旧吸附测试硬编码91px，当前桌面收缩高度已为45px。它属于设计变化后的验收标准漂移；不能把所有失败都归因于无头动画时序，也不能为了绿色结果直接扩大误差。

建筑 SVG 曾被用户指出轮廓未闭合、主体不清楚，是目视质量不足的历史反馈；XML可解析和无横向溢出无法替代照片对照。本轮没有重新评价重绘后的视觉质量。

### 3.7 合并和文档维护没有保持最新有效决定

Git 证据：队友 `20f1380` 移除 AGENTS 跟踪并增加忽略，后续我方合并 `7c9a6c5` 又恢复跟踪，最终 `0376ee8` 再移出。这是合并时没有保留队友文件管理意图的实际错误，目前已修正。

历史中曾按用户确认修订8份文档，后续同步时保存在 stash/备份，没有恢复覆盖队友。保护成果是正确的；但旧版本因此仍留在当前入口，不能把“本地备份有正确说法”当成共享文档已修正。

当前 README 的“尚待提交”、STATUS 的“教师仅简介/楷体”、DESIGN 的旧页头高度等，都需要按当前代码及用户最新决定对齐。统一到 STATUS 的队友整理值得保留；集中到一个文件之后仍要替换失效条目，不能只追加更正。

## 4. 对队友批评的逐项判断

| 批评 | 证据支持的判断 | 应避免的过度结论 |
|---|---|---|
| 属性东一个西一个 | 栏目身份、父级、路由、展示位置及页头样式确有分散维护 | 不是所有分文件都错误；按职责分模块应保留 |
| 组件不会复用 | 静态/动态卡片行为已分叉，内页风格曾逐页补齐 | 公共头尾和独立控制器已有复用；生成 HTML 数量不是重复源码证据 |
| 接口乱写 | 内容字段和模板绑定缺少稳定契约，精确字符串替换已失效 | 目前没有公共 REST 写入 API，不能无证据称到处乱造 API |
| 文档乱写 | 历史决定、当前实现、部署版本和验收证据混杂，有明确旧结论 | 历史回执应保留日期；不能为统一“当前”删除追溯证据 |

问题主要来自我们前期快速补功能时没有收拢结构。队友近期动画也有缺陷，说明修视觉不能自动修架构；应按具体模块和变更归因，不按开发者或模型一概而论。

## 5. 建议的目标结构

保持现有 Node 构建和原生 JavaScript，按以下职责逐步拆分；名称为建议，尚未实施：

```text
frontend/src/data/
  栏目注册表：稳定id、父级id、现有URL、标题、排序、布局、旧标识别名
  教师与默认素材：保留真实资料、来源和占位
frontend/src/templates/
  公共外框、具名数据槽位、卡片和图文区块
frontend/scripts/
  构建入口、配置校验、静态输出、Django预览适配、产物清单
frontend/src/js/
  菜单状态控制、通用文字动画、既有页头/图片/过渡模块
frontend/src/css/
  设计参数、组件规则、响应式规则（先按组件整理，再决定拆文件）
```

Django 和博达分别是输出适配目标，不能将 Django 标签转成 JSP 就宣称已完成博达接入。博达组件语法、资源上传与实际字段必须在学校环境验证。共享的是栏目含义、组件结构和资源规范；各平台保留自己的数据读取方式。

稳定标识调整也不是全局搜索替换：先建立旧key/URL兼容表，保留原路径和已发布资料。涉及持久化数据迁移时再备份、制定映射、在隔离库验证，当前阶段先做前端配置整理。

## 6. 分批实施与验收

| 批次 | 范围与顺序 | 交付与验收条件 |
|---|---|---|
| A 固定基线 | 保留队友效果、现有URL、完整教师资料；整理有效检查和旧断言；将同日复现转为正式回归检查 | 检查先能检出已知问题；历史结果不冒充新验收；记录桌面/窄屏/减少动态效果下的预期 |
| B 菜单缺陷 | 统一目标打开状态；动画可取消；完成回调不能覆盖后续意图；屏宽、减少动态效果、关闭父级时统一清理 | 快速开关、Escape、父子菜单、窗口切换均正确；逻辑、ARIA、焦点、inert与最终视觉一致 |
| C 栏目与模板 | 先迁一个科研集合和页脚二维码：归一URL后判当前项；栏目注册表生成导航和面包屑；具名槽位替代全文匹配 | 17个既有导航入口当前态正确；只改标题、排序或空白不改变内容归属；必要槽位缺失/重复使构建失败 |
| D 组件与样式 | 统一教师卡、栏目卡、正文图文的输出契约；整理页头覆盖规则；复用已认可分区样式 | 静态与动态卡片图片反馈一致；动态发布正文、空值、长标题和窄屏均检查；公共样式调整覆盖所有相关页面 |
| E 产物与学校试点 | 内容哈希资源版本；仅按产物清单处理旧生成文件；先做博达首页、新闻列表、详情最小链路 | 源资源删除后不打包旧文件；相同输入产物稳定；学校后台发布一篇测试文章并验证资源、导航和正文，取得实际证据后再推广 |

批次B可先修已知交互缺陷，不必等待整站结构改完。批次C也不要求一次重写构建器，应以单个组件证明契约后逐步替换。

清理构建产物时只能处理确认由本构建生成的旧文件，不能递归清空共享 preview 目录。当前复制脚本不删除旧输出是为保护队友文件；引入产物清单才能同时解决保护与陈旧资源问题。

每批重新构建静态与 Django 外框，并运行与改动相关的现有检查。涉及动态内容时必须查 Django 实际渲染；涉及学校适配时必须查博达实际模板。修源码后仅看静态预览不能完成这两类验收。

## 7. 保留项、暂缓项和本轮结果

保留公共外框、独立页头/图片/跨页控制器、原创芯片装饰、现有栏目URL、教师完整资料、新闻审核事务与发布快照、源码与生成目录分离。装甲宋自托管和素材来源记录也应保留。

暂缓整体换React、重建通用CMS、扩展公开API、批量改数据库标识、未经学校试点就制作整站博达包，以及把建筑审核素材接到正式页面。这些工作目前没有足够收益或验收依据。

未发现可以确认的“演示直接写数据库”违规：历史回执记录的是后台UI录入，不能把早期模糊说法盖过用户随后明确要求。代理修复有单独授权，也不能将其算成未经授权越界。

本轮完成历史阅读、远端与代码基线核对、源码与既有实验证据交叉核查、分析报告及STATUS入口更新。未修改业务源码，未操作业务库、服务器或博达后台；未恢复stash，未提交、推送或部署。实施批次尚未开始。
