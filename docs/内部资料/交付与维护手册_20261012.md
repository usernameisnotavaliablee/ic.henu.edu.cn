## 2. 本机运行

前端从仓库根目录执行 `node frontend/scripts/build-site.js`；用标准库 HTTP 服务绑定 127.0.0.1:8766 查看 preview。静态版的占位条目不能验证后台发布效果。

动态运行按 [backend/README.md](../../backend/README.md)，使用自己的隔离数据目录和已有 Python 环境。此机器有 Python 3.10 的 sandbox/.venv，部分依赖在 sandbox/test-deps；字体工具另有 sandbox/conda-envs/font-tools。队友可以创建自己的隔离环境，按 requirements.lock 安装；不向 Anaconda base 或全局环境安装项目依赖。

已有库不执行 bootstrap_preview、seed_showcase 或任何导入命令。start-local.ps1 内含 bootstrap，不能盲目用于现有业务库。新演示内容通过后台 UI 录入，不把演示正文硬编码到前端数据文件。

## 3. 后台访问与新闻通知操作

后台通过保持运行的 SSH 隧道访问：`ssh -N -L 8095:127.0.0.1:8095 <已授权用户>@47.94.146.53`，浏览器打开 http://127.0.0.1:8095/preview-admin/。账号、口令和 SSH 密钥私下交接，不放文档。隧道退出后入口不可用，不应为方便而开放后台公网端口。

新闻与通知：

1. 新增草稿，slug 以 news- 或 notice- 开头，创建后固定；填标题、摘要、正文、来源、展示日期、配图和图注，演示内容明确标记。
2. 正文使用空行分段；小标题如 `## 说明性质` 独占一段，前后空行。普通单次换行保留；HTML 不执行。
3. 只保存表示草稿，前台仍读旧快照；勾选“保存后提交审核”后交审核员。
4. “查看草稿并审核”中批准、退回或撤下。退回保留旧快照；撤下使列表消失、详情 404。
5. 前台核对首页摘要、列表、详情及分页；保存/审核遇到版本冲突应保留编辑文字，重新打开后核对，不覆盖队友成果。

新闻通知每页 10 条；Publication 才是前台数据。不能在数据库里直接编辑快照代替审核。

## 4. 教师、栏目、轮播和站点

“教师、栏目与站点资料”中编辑草稿，返回列表勾选并执行“将所选资料发布到预览前台（含撤下设置）”。仅保存不生效；教师/集合条目撤下需关闭“前台展示”后再发布。固定区块会保留待更新提示，轮播关闭后仍显示默认项，并非完全移除。后台不提供删除按钮，保留记录。

- 固定区块：使用既有内容位置，学院概况有 section-1/2/3。
- 新增栏目条目：选择新增栏目文章/方向/平台/课题组，填写 entry- 开头唯一地址标识及所属集合；不是在同一固定区块里堆积所有文章。
- 教师：选择既有教师或新增 teacher- 标识；程纲、张锦龙、郑海务底稿不得被演示文案覆盖。顺序依 sort_order，再按 key。
- 课题组：选择已发布研究方向，每个组关联一个方向，同一方向可供多个组选择。
- 轮播：六个 home.slide-1 至 home.slide-6 位置，对应标题、副标题、简介、图及图注；它不是无限新增幻灯片的后台。
- 站点：key=site，维护院名、英文、院训、标识、联系信息、公众号名称/二维码和页脚说明；空值在部分合并字段中回退为默认配置，不等于清空所有前台默认值。

ContentEntry 没有 Article 的同款 revision 检查、独立提交审核状态及同款 AuditEvent。多人并发编辑、分权及审核流程需队友评估完善，不能直接承诺“所有资料均经过双人审核”。

## 5. 图片、字体和二维码

图片在 frontend/src/assets 添加并记录来源，构建后进入 preview/assets。ContentEntry 图片选项扫描 jpg/jpeg/png/webp，新闻配图另有固定 IMAGE_CHOICES；必要时更新模型选项并生成迁移。禁止把外部示意图称为学院真实设施或活动现场。

二维码同样从 assets 选取。未获正式公众号二维码不生成冒用占位。无上传入口，不把任意服务器路径填进字段。

字体优先访客本机楷体，缺失时用本站开源字体。修改固定标题/校训需跑 prepare-fonts.py --check；字符不足时在隔离环境重新生成并构建，保留许可证。不能复制 Windows 商业字体给所有访客下载。

## 6. 发布、备份、恢复与日常维护

详细流程见 [deployment/README.md](../../deployment/README.md)。发布必须对应明确 Git commit，备份库和必要配置，生成新 release 后验证并切换，不把代码发布与业务数据覆盖混为一件事。

SQLite 使用 sqlite_backup.py 的一致性备份接口；先校验备份，再在隔离副本演练恢复。完整业务库恢复需要核对迁移、文章/快照/栏目数量、教师、图片、草稿审核及账号登录。标准库样例备份测试通过不代表这些已完成。

日常检查 healthz、进程状态、磁盘容量、备份可用性、异常日志、素材请求和过期依赖；检查频率、告警接收人及备份保留策略由接手人落实。日志和备份不入库，不向聊天输出密钥。
