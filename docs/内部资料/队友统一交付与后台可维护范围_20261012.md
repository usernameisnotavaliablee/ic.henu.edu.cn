## 1. 先说明真实完成程度

后台功能已经实现，接口说明也已写，不是只有设计稿。当前以 Django 后台表单及前台 HTML 路由提供功能，没有额外的公共 REST 写入 API；队友可以从实际接口与数据说明_20261012.md 查路由、字段、权限、数据流程和栏目映射。

“所有占位内容可通过后台修改”尚未完全达到。主要业务正文已有后台，但部分首页文案/配图、固定空位、展示控制和界面标签仍在源码。不能以能修改源码替代这一后台维护要求，也不能把这些未完成项只归因于学院缺材料。

本轮只核查、完善交接和 Git 忽略规则，不新增后台字段、不改业务库、不改变线上运行代码。下表缺口交队友继续实现。

## 2. 现有后台能提供什么

| 内容 | 当前后台能力 | 限制或补充 |
|---|---|---|
| 新闻、通知 | 标题/摘要/正文/来源/日期/图注、现有配图、草稿审核发布撤下、分页 | 图片固定白名单，不能上传；审核有 revision 冲突保护 |
| 学院简介、组织机构、领导班子 | 固定位置 about.section-1/2/3，发布正文、摘要和图片 | 外层栏目标题/英文/背景大字仍固定；资料标题作为内容标题，不改外层标题 |
| 科研、党建、招生、培养、服务等集合 | 21 个集合可新增 entry-* 条目、分类、排序、发布与撤下 | 集合本身的名称、英文、布局、导航层级由代码定义 |
| 研究方向与课题组 | 方向详情、课题组详情及已发布方向关联 | 每组当前一个方向；一方向可供多个组选择 |
| 教师 | 三位默认教师的资料覆盖、新增 teacher-*、照片/来源/排序及撤下 | 默认资料可被发布快照覆盖；固定“教师资料待补充”卡片没有后台开关 |
| 六个首页轮播位置 | 标题、副标题、简介、图注及已有素材替换 | 数量、顺序和结构固定；is_visible=false 实际回退默认内容，不能真正隐藏该张 |
| 站点名称、英文、院训、页头/页脚标识 | key=site 中编辑发布，动态外框读取 | 不是所有页面内重复文案都绑定 site，例如培养区配图上的固定校训文案 |
| 办公地址、电话、邮箱 | 联系页与页脚读取 site 发布资料 | 缺失显示占位；部分 site 字段空值会回退默认值，不等于明确清空 |
| 公众号名称、二维码 | 从运行素材中选择二维码并发布 | 无上传；无二维码时显示默认占位和说明文字 |
| 页脚备案/平台说明 | site.body 可发布替换占位 | 只填学校确认的信息；版权行的“内部演示版”等文案仍固定 |

代码依据：backend/content/models.py、entry_admin.py、editable.py、collections.py、views.py；frontend/scripts/build-site.js；backend/templates/site/overview_content_block.html、wechat.html、vacancies.html。content-catalog.json 当前含 32 个固定插槽/轮播位置、21 个集合，另加教师及 site，并不是全站每段文字都有对应插槽。

| 首页科研三个图文入口 | 图片、标题、图注和链接写在 home.html | 提供可维护内容字段或明确复用现有条目；来源/授权说明必须保留或同步更新 |
| 首页培养图片与说明 | 校园牌坊、固定校训及“正式素材待替换”仍在 home.html | 能换图片、alt 和说明；不能只替换图片却留下不对应的图注 |
| 教师空位卡片 | vacancies.html 始终输出三张空位卡片，由构建脚本生成 | 能关闭/配置，或根据实际教师数量按明确规则自动移除；新增教师不能永久保留三张固定占位 |
| 轮播启停/顺序 | 六张默认结构固定；撤下回退默认素材 | 实现真正发布后停用/排序，确保圆点、总数、alt 和键盘/读屏状态与可见项一致；无须因此引入复杂 CMS |
| 全站固定界面文案 | 导航/栏目标题/英文/背景字、页脚链接、技术支持、开发预览提示等来自源码 | 对业务占位逐项明确后台字段；固定导航/设计配置与合规提示另行明确维护方式，不把它们笼统标成后台可改 |
| 图片/附件工作流 | 只能选既有图片；没有上传入口或通知附件模型 | 若要让编辑独立换新素材，补受控上传/资源维护及权限测试；正式附件需求待确认，不能先写成已有能力 |

补齐建议保持简单：优先复用 ContentEntry 和现有发布快照，不另起一套通用 CMS；相同文案尽量复用一个来源。更改源文件后必须构建静态与 Django 外框，不直接改 generated。

每一项的验收应通过后台 UI 修改、保存、发布，再检查实际 Django 动态首页/内页；草稿不提前生效、撤下语义明确、无旧占位残留。不要只核对纯静态 preview。新增内容维护能力还需要队友的多角色和安全验证。
