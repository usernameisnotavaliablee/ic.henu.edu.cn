## 新增字段与发布语义

在 Django 后台 `/preview-admin/` 的“教师、栏目与站点资料”中维护。字段均加入现有 ContentEntry；一份资料只有一条记录，前台读取 published 快照。

| 字段 | 类型 / 长度 | 使用位置与约束 |
|---|---|---|
| teacher_category | 可空字符串，40 | 仅 teacher-*；选项来自 faculty-categories.json。空值表示待分类，仍显示在完整名录 |
| service_url | 可空 URL，200 | 仅大型仪器集合或其固定位置；只接受有效 HTTP/HTTPS URL |
| service_label | 可空字符串，80 | 外部服务入口文字；填写时须同时提供 service_url；空值由前台显示“进入仪器共享服务平台” |
| website_qr_image | 可空素材名，100 | 仅 key=site；选择已归档的运行图片，与原 qr_image（公众号）独立 |

前端六类人才及普通教师的稳定 ID、优先级与三档样式见维护对照；旧 other-talent 仅兼容，不继续生成正式分组。三人完整资料保留，人工顺序为程纲、郑海务、张锦龙。前端支持多称号及每个称号的年份；旧 Django 表单仍仅单分类，本轮没有新模型或迁移。

教师分类页使用共享三档组件，复用完整名录的唯一资料和详情地址；在分类页点击教师后仍沿用主线的教师详情面包屑，不建立重复个人页面。分类定义只在前端数据文件维护，构建生成 backend/content-catalog.json 供后台表单和读取器使用。

资料流程：编辑并保存草稿 → 在列表勾选记录 → 执行发布动作 → 到前台确认。保存草稿不会改变已发布分类、二维码或服务链接；发布需 content.publish_contententry。资料发布不等同于新闻的提交/审核状态机，没有新增公共 REST 写接口。

新闻发布继续使用原流程：`/preview-admin/content/article/` 新增或编辑 → 保存/提交审核 → 草稿审核页批准 → 前台 Publication 快照；审核需 content.review_article。新闻接口、冲突检查、权限和撤下语义未因栏目调整而替换。

新增教师使用“新增教师”位置并填写 teacher-* 标识；新增机构、制度、认证和仪器材料使用“新增栏目条目”，填写 entry-* 标识并选择表中集合。仪器正文可写名称、用途、规格、共享规则；外部 URL 由维护者核实后填写，前台不代理请求该服务。学生制度日期越新越靠前，同日按稳定标识排序，空日期排后；其他集合仍按原排序字段和日期规则。

公众号与网站二维码留空时均隐藏对应区域；填入并发布后联系页与页脚显示，已有版式保留。没有自动生成二维码、上传图片或 Word 自动解析功能；需要新图片时先由开发人员归档素材、构建，再供后台选择。

迁移 `0008_meeting_content_fields` 只增加四个可空字段；0006/0007 继续负责主线芯片图片转 JPG 的兼容。迁移与字段测试只运行于隔离库。后续更新现有环境前按根目录[后端交付文档](../后端交付文档_博达接入与预览部署.md)备份，并检查完整迁移计划，不运行 seed/bootstrap。

## 字体与移动端

会议“顶栏采用微软雅黑”按顶栏范围实施，包括品牌区校训；使用 Microsoft YaHei 优先的系统字体栈，不打包商业字体。栏目装甲宋标题、页脚校训、主线动画、芯片 JPG、面包屑和链接反馈保留。系统未安装微软雅黑时按字体栈回退。

新层级复用独立导航组件，手机展开按钮与真实链接分开；栏目和管理入口保持可点击区域。新增页面在 1440、768、390、320 宽度检查溢出、唯一 ID、三级导航和空态，并查看桌面及手机截图；真机触感和网络性能仍需另验。

## 材料收集与博达对接

以下是统一资料字段清单，可用于学院整理 Word；本轮不修改用户既有 Word 文件，也未实现自动导入。

| 材料 | 需学院提供/核准 |
|---|---|
| 教师 | 姓名、职称、经审定的人才分类、完整简历、研究领域、经同意公开的联系方式、照片、来源/授权、审稿人和日期 |
| 管理机构 | 正式机构名称、成员/职务、职责正文、排序、审稿人和日期；委员会名称和职责单独确认 |
| 研究方向/课题组 | 名称、简介、正文、团队与方向关联、公开成员、图片及说明、来源/授权、审稿人 |
| 大型仪器 | 名称、型号、用途、图片/图注、使用规则、外部服务平台 URL 与按钮名称、发布日 |
| 制度与工程认证 | 标题、适用对象、正文、文件编号（如有）、发布/生效日期、来源、审稿人；区分学生制度和行政流程 |
| 站点资料 | 学院中英文名称、校训、标识、公开地址/电话/邮箱、公众号名称和二维码、正式官网二维码及确认人 |

“毕业生资格审核”不直接写入学术委员会职责；先请学院确认是学术委员会、学位评定分委员会或其他机构。“18 日”按待协调的初步部署/学院预览节点记录，不承诺正式上线。

博达仍需平台维护人员与熟悉系统的学长确认实际版本、权限、匹配手册和资料导入能力。先打通首页新闻 → 列表 → 详情 → 新增/修改/撤下，随后绑定上述栏目与字段。Django 字段名是预览实现，不是博达组件语法；不能直接把数据库或 Node 源码导入博达当作已部署。前端负责模板与响应式，平台维护负责栏目/资料源/发布，学院负责事实与授权审定。
