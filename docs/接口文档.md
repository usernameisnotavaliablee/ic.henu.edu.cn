# 前端交付与后端从零实现接口文档

版本：v1 草案 · 2026-10-15 · 原功能核对基线 bc7cc40；当前前端补充基线为 f59755f 加 codex/frontend-refactor 本地修改（未提交）。

> 本轮按已确认前端更新栏目映射、人才多称号/年份、空态和维护边界。栏目表由 columns.js 生成；详细展示字段见[内容维护对照](../frontend/CONTENT-MAINTENANCE.md)。A/B 节仍是新后端方案，拟定 JSON API 尚未实现。现有 Django 只做兼容预览，博达后台发布链路尚未验证。

**交接前提：后端同学只拿到前端，没有现成数据库、接口、登录系统或管理后台，需要从零实现。** 本文覆盖前台取数和后台录入、编辑、审核、发布、撤下；后端可选择自己的语言、框架和数据表，不要求复制现有Django工程。

**区分三个状态：**第0节是现有系统已做出的功能和真实地址，作为重建依据；A1—A9为新后端公开读取接口方案；B1—B6为新后端管理与发布接口方案。所有 `/api/v1/...` 均待实现，当前前端也尚未接入这些JSON接口。现有线上系统使用Django表单和服务端渲染，不能将两套地址或响应格式混用。本轮未新增 JSON 接口、未操作实际业务库或发布正式内容。

## 0. 从零开发需要保留的现有能力

### 0.1 已有功能和实际接口

以下是**已经实现的现有系统**，不是拟定API。后台基址为本机/SSH隧道 `http://127.0.0.1:8095`，需要登录session、CSRF及相应权限；公网8099不提供管理入口。表单POST使用 `application/x-www-form-urlencoded`，返回HTML/重定向，不是JSON。id是管理记录主键，slug是公开URL标识，两者不能混用。

| 已有操作 | 方法与实际路径 | 关键参数/结果 |
|---|---|---|
| 后台登录 | GET/POST `/preview-admin/login/` | username、password、csrfmiddlewaretoken；认证成功建立session |
| 新闻通知草稿列表 | GET `/preview-admin/content/article/` | HTML列表，按权限查看 |
| 新建新闻或通知 | GET/POST `/preview-admin/content/article/add/` | 正文字段 + expected_revision=0；保存后得到id，初始revision=1 |
| 修改草稿 | GET/POST `/preview-admin/content/article/{id}/change/` | 提交完整可编辑表单与expected_revision；slug创建后只读；编辑不直接改前台 |
| 保存并提交审核 | 同上新增/修改路径POST | 加 submit_for_review=on；不勾选则只保存草稿 |
| 查看待审核稿 | GET `/preview-admin/content/article/{id}/review/` | 返回审核表单与当前expected_revision |
| **批准发布新闻/通知** | **POST `/preview-admin/content/article/{id}/review/`** | **decision=approve、expected_revision、CSRF；批准submitted稿，复制到Publication，前台可见** |
| 退回修改 | 同一review路径POST | decision=return；保留之前的前台快照 |
| 撤下新闻/通知 | 同一review路径POST | decision=withdraw；删除前台快照，草稿仍在，公开详情404 |
| 教师/栏目/轮播/站点草稿列表 | GET `/preview-admin/content/contententry/` | 现有后台统一管理位置；新后端不必复制这张大表 |
| 新增/修改资料草稿 | GET/POST `/preview-admin/content/contententry/add/` 或 `/{id}/change/` | 按位置提供字段，保存不自动发布 |
| 发布资料/教师/栏目 | POST `/preview-admin/content/contententry/` | action=publish_selected、_selected_action为所选记录id、CSRF |
| 撤下教师/栏目资料 | 先修改草稿，再执行上述发布动作 | is_visible关闭后再次发布，才影响前台 |
| 查看新闻发布快照/操作记录 | GET `/preview-admin/content/publication/`、`/preview-admin/content/auditevent/` | 只读，按模型权限访问 |

**新闻发布的真实请求结构**（id=123、revision=4及token仅为示意，不能直接拿去操作真实数据）：

```http
POST /preview-admin/content/article/123/review/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded
Cookie: sessionid=<当前登录会话>; csrftoken=<当前CSRF-cookie>

csrfmiddlewaretoken=<当前审核表单token>&expected_revision=4&decision=approve
```

审核成功通常302跳回 `/preview-admin/content/article/` 并显示成功消息；校验/状态/审核版本冲突会在200 HTML表单中显示错误，不能只看HTTP 200判成功。草稿保存时的并发冲突可能为表单错误或409文本；无审核权限403、缺CSRF403、匿名通常302到登录；公网管理入口404。登录会更新CSRF状态，须使用当前表单值。正常录入走后台网页，此示例用于说明接口，非本轮执行操作。

| 现有新闻表单字段 | 类型/限制/用途 |
|---|---|
| category、slug | news/notice；slug最长80，news-或notice-开头且创建后固定 |
| title、summary、body | 必填文本，最大160/400/30000字符；正文纯文本 |
| source、date | 来源最长100；date=YYYY-MM-DD或空字符串 |
| image、image_alt | image从现有图片白名单选文件名，不是上传；说明最长200 |
| is_placeholder | 复选框，示例内容标记；不会自动加【演示】前缀 |
| expected_revision | 必填版本，新建0、修改/审核从当前页面读取 |
| submit_for_review | 勾选为on，保存后进入submitted；省略为仅保存 |
| csrfmiddlewaretoken、_save | CSRF表单字段；_save为标准保存按钮字段，审核页不依赖它 |

现有新闻编辑需add/change_article权限，查看审核页需查看权限，审核/撤下另需review_article；资料发布另需publish_contententry。现有资料没有新闻同款独立审核状态机和revision保护，不能宣称所有资料都已双人审核。当前两个模型均禁止后台删除。旧 Django 轮播撤下仍回退默认；教师固定空位已撤除。前端可表达多称号及各自年份，旧后台仍只能维护单一分类，没有相应年份字段。

现有公开接口也需保留页面行为：GET/HEAD `/`、`/index.html`、`/news.html?page=1`、`/notices.html?page=1`、各栏目/教师/文章 `.html` 返回HTML；`/healthz`返回JSON状态；`/css/`、`/js/`、`/assets/`提供资源。未发布详情返回404。完整维护细节另见[现有Django说明](现有Django预览接口说明.md)，本文后续的新契约不依赖该文件才能实施。

### 0.2 只有前端时，后端实际要交付什么

1. 存储和资源服务；保存文章草稿、已发布版本、教师/栏目/站点资料、关联关系和排序，不能把示例硬编码成永久返回值。
2. 可用的管理界面：登录、草稿列表、编辑表单、提交/审核/发布/撤下及错误反馈。**frontend目录不含可直接独立运行的管理后台**，现有后台UI在backend目录；只交前端时这部分也要由后端同学提供，允许使用合适的管理框架。
3. A节的公开读取能力与B节的管理能力，及原HTML路径的路由兼容；如选服务端模板渲染，可用等价绑定，但字段、发布规则和验收不省略。
4. 前后端连接：现有HTML有版式和JS交互，没有调用拟定JSON接口的业务请求层。需要前端补请求适配器，或由新后端输出同样DOM；**只搭接口、直接打开旧静态HTML不会自动获得后台内容**。
5. 配置示例、初始化管理员方式、运行/迁移/备份说明与最小联调数据。账号和密钥不放前端包；不强制用Django/SQLite或原表结构。

建议交接包为frontend源码、scripts、licenses、可查看的preview，以及本文、[前端组件契约](../frontend/CONTRACTS.md)、[学校交接边界](../frontend/BODA-HANDOFF.md)。旧Django适配代码只作参考，不是新后端运行依赖。现有三位教师完整底稿在frontend/src/data/teachers.js，栏目树在columns.js，运行素材在src/assets；有审定/授权要求的材料不能因在包里就默认可正式发布。

只有前端无法恢复服务器上已有新闻、账号、审核日志或已发布快照。若要保留线上内容，需另行提供经授权的数据迁移材料；静态news-preview不是业务数据库备份。新空库可通过后台录入/经审查导入正式基础资料，演示内容经后台录入；不得对已有业务库运行初始化覆盖。

## 1. 分工与页面需求

前端负责布局、字体、动画、栏目树、现有URL、面包屑，以及加载/空数据/缺图/失败状态；后端负责存储、后台维护、审核发布、图片资源、分页排序和数据一致性。访客页面使用A节公开读取接口；管理界面使用B节受认证的读写接口，不能向普通访客发管理token。旧Django表单地址是已有功能证据，新后端的管理契约见第5节。

## 2. 通用约定

联调域名/端口由后端提供，建议前端同源访问 `/api/v1`；开发跨源时只允许约定的开发origin。当前源码尚无此API基址配置和请求适配器，不能仅部署接口便认为前端已经接通。

- A节公开接口均为GET；B节管理接口按表中GET/POST/PUT/DELETE。拟定JSON请求/响应均使用application/json、UTF-8；带正文请求加Content-Type，所有请求加Accept。第0节的旧表单接口使用它自己的表单协议。
- JSON用camelCase。表中字段均须出现；只有标明可空的单值用null；无集合内容用[]，不返回null数组、假文章或“待提供”假对象。
- id/slug均为稳定字符串，不随排序变化；不要求使用数据库主键。服务端输出有序数组，前端不重新排序。
- 日期为YYYY-MM-DD，不知道就null，不能用发布时间代填展示日期。后续时间戳须为带时区的ISO 8601。
- 图片/页面URL返回站点根相对路径或约定的HTTPS地址，前端直接使用，不再拼assets/、.html或文件名。本地HTTP预览地址不作为正式外链规则。
- A节公开接口只读已发布、可见内容。不存在、未批准、已撤下一律404；关联卡片、首页和缓存同样不泄漏草稿。B节仅在认证授权后可读写草稿。
- 可选文字没有值时按字段约定返回null或空字符串；前端决定占位或隐藏，后端不把“待提供”存为事实。
- 演示内容isDemo=true且标题/姓名带【演示】；真实教师资料不加演示标签。本文样例只用于协议说明，不录入业务库。
- v1内容响应建议 `Cache-Control: no-store`，图片可独立缓存。发布/撤下须同步影响首页、概览、列表、详情与关联数据，不能继续公开旧缓存。

成功格式（data形状按接口定义）：

```json
{"data": {}, "requestId": "contract-example-001"}
```

失败格式（非2xx）：

```json
{"error": {"code": "CONTENT_NOT_FOUND", "message": "内容不存在或不可访问"}, "requestId": "contract-example-002"}
```

requestId为后端生成的非空排查编号，不含凭据。成功只含data/requestId，失败只含error/requestId，不以200加错误文案伪装成功。

| HTTP | error.code | 前端处理 |
|---|---|---|
| 400 | INVALID_ARGUMENT | 参数错误，不当作空栏目 |
| 401 / 403 | AUTH_REQUIRED、INVALID_CREDENTIALS / PERMISSION_DENIED | 管理会话失效、登录失败或无权限；不能自动重试写入 |
| 403 | CSRF_FAILED | 更新会话/CSRF后由用户重新操作，不盲目重复提交 |
| 404 | CONTENT_NOT_FOUND | 内容不存在/不可访问；对应HTML详情也应返回404 |
| 409 | REVISION_CONFLICT / INVALID_STATE / SLUG_CONFLICT | 草稿已变化、动作状态不允许或地址冲突；重新核对后操作 |
| 422 | VALIDATION_FAILED | 管理表单字段校验失败，展示对应字段错误 |
| 429 | RATE_LIMITED | 稍后重试，遵循Retry-After（如提供） |
| 500 / 503 | INTERNAL_ERROR / SERVICE_UNAVAILABLE | 加载失败和重试，不显示“暂无内容” |

公开接口不重定向后台登录；超时、非法JSON与网络失败均不是空数据。

B节422的error可附fieldErrors（字段路径→错误字符串数组）；409 REVISION_CONFLICT可附currentRevision整数。错误不得泄漏密码、数据库异常栈或未授权正文。写请求超时后先重新GET核对revision/状态，不能直接认定成功或自动再发布。

### 分页

query中page默认1；pageSize默认10，cards集合默认9。均为正整数，pageSize上限50，非法值返回400。超过最后一页返回200和空items、真实total；这与旧Django跳到最后一页不同，需要新适配器按此约定处理。

分页data：

```json
{"items": [], "page": 1, "pageSize": 10, "total": 0, "totalPages": 0, "hasNext": false, "hasPrevious": false}
```

total是筛选后全部已发布条数，不是本页长度；totalPages=ceil(total/pageSize)，hasNext=page<totalPages，hasPrevious=totalPages>0且page>1。空栏目保留入口。v1不支持任意排序、关键词搜索或未列出的筛选参数。

## 3. 共用类型

`T[]`表示有序数组，`T|null`表示可空。下列对象字段都须出现。

### Media、Source、Body

| Media字段 | 类型 | 约定 |
|---|---|---|
| url | string | 图片可用地址，不是文件系统路径 |
| alt | string | 非空图片说明，不拿文件名代替 |
| width / height | integer | 正整数，原图尺寸，供预留比例 |
| caption | string | 图注，没有则空串，示意图不得标成新闻现场 |
| source | Source或null | 素材来源；有来源URL不等于已获公开使用授权 |

`Source={label:string,url:string|null}`：label非空；不能传拼好的a标签。

非空图片对象示例（路径、尺寸为协议样例，实际响应必须是可访问资源及其真实尺寸）：

```json
{
  "url":"/media/example-campus.jpg","alt":"【演示】校园建筑配图",
  "width":1200,"height":800,"caption":"协议示例图片，非新闻现场",
  "source":{"label":"图片来源待实际素材确认","url":null}
}
```

`Body={format:"plain",text:string}`：全文不截断。空行分段，`## `小标题独占一段，HTML作为文字转义。v1不接收富文本HTML、任意Markdown或脚本。教师完整简介、课程、论文、经历及公开联系方式可分小标题保留在text中，不能只返回卡片摘要。

### ContentSummary、ContentDetail

| ContentSummary字段 | 类型 | 含义 |
|---|---|---|
| slug / url | string / string | 稳定标识、可进入全文的真实页面地址 |
| title | string | 非空标题，建议不超过160字 |
| summary | string | 摘要，可空串，建议不超过400字，视觉截断由前端做 |
| displayDate | string或null | 展示日期 |
| cover | Media或null | 缺图返回null，前端使用统一缺图版式 |
| source | Source或null | 文章来源，与图片来源区分 |
| isDemo | boolean | 是否虚构演示 |

`ContentDetail`为上述全部字段加 `body:Body`。概览和列表只展示摘要，详情显示全文。

### 教师

`TeacherSummary={id,slug,url,name,subtitle,summary,portrait,sortOrder,awards,isDemo}`：id/slug/url/name/subtitle/summary为string，id稳定且唯一、name非空；subtitle是完整职称/领域展示行；portrait为Media|null；sortOrder为非负整数；awards为`{categoryId:string,year:integer|null}[]`，同一人同一称号只能一条，年份可空；isDemo为boolean。称号ID、优先级和展示档次遵循前端 faculty-categories.json，不根据履历推断称号。

`TeacherDetail`=TeacherSummary + `body:Body` + `source:Source|null`。

`TeacherDirectory={items:TeacherSummary[],total:integer}`：total等于items长度；不输出虚构教师空位。名录返回全部可见教师，分类页按六类人才及普通教师分组。国家级领军人才、国家级青年人才配置showWhenEmpty=true，无人时保留标题及整理中提示；其他类别无人整体隐藏，showWhenEmpty缺省为false。显式enabled=false仍隐藏；未分类教师仍出现在完整名录，不自动算普通教师。同一教师多称号只维护一份详情。名录按人工sortOrder及id排序；首页按最高称号优先级、人工顺序、id去重取最多三人。当前人工顺序为程纲、郑海务、张锦龙；完整资料保留。

## 4. 接口定义

以下9个接口均为待实现方案；示例中的空数组是真正空数据，不是要求永远返回占位。

### A1 GET /api/v1/site — 全站资料

无参数。data：universityName/collegeName/englishName为string；motto/filingText为string|null；logo为Media|null；contact的address/phone/email各为string|null；wechat与website各含name:string|null、qrCode:Media|null；friendlyLinks为`{id,name,url,group,sortOrder,enabled}[]`，group为internal/external。

```json
{
  "data": {
```

### A2 GET /api/v1/home — 首页聚合

无参数，一次返回同一发布口径的数据，避免新闻文字与图片各请求一份导致错位。

| data字段 | 类型/规则 |
|---|---|
| slides | Slide[]，启用项按后台顺序，数量由数据决定，关闭项不返回 |
| news | ContentSummary[]，news类别前4条，图片新闻共用此数组 |
| notices | ContentSummary[]，notice类别前3条 |
| research | ResearchFeature |
| education | EducationFeature |
| teachers | TeacherDirectory，与A8同一资料源，按最高称号排序去重取最多三人；total为本响应items长度 |

`Slide={id,theme,title,eyebrow,text,note,image}`：前六项string；id使用稳定的home.slide-<标识>，现有1至6保持兼容，排序变化不改id；theme仅chip/campus/technology；image为Media|null。chip且image=null用现有原创芯片装饰，其他theme须有image。无轮播时展示静态品牌区，单条隐藏控制按钮；圆点/计数/读屏以真实条数生成。后端不返回SVG代码。

`FeatureLink={columnId:string,title:string,summary:string}`，columnId见附录，前端解析URL。

`Topic={columnId:string,title:string,image:Media}`。

`ResearchFeature={intro:string,description:string,illustrationCaption:string,links:FeatureLink[],topics:Topic[]}`。现有两个主要入口为platforms/groups，三个配图入口指向research-directions/research-progress/education；原创芯片插画由前端保留。

`EducationFeature={intro:string,description:string,links:FeatureLink[],image:Media|null}`，入口为disciplines/curriculum。图片来源/图注在Media中。links/topics无内容时返回[]，前端保持相应空态与固定栏目入口。

## 5. 从零实现后台：管理与发布契约（B节，待实现）

本节定义现有业务能力在新后端中的JSON方案；不能把第0节的真实Django地址误当这些地址已经上线。管理UI可由后端框架提供，数据表不受本节命名约束。

### B1. 会话与权限

| 方法与路径 | 请求 | 响应 |
|---|---|---|
| GET `/api/v1/admin/session` | 无 | 200，data={user,permissions,csrfToken}；未登录user=null、permissions=[]，仍给登录用csrfToken |
| POST `/api/v1/admin/session` | JSON {username:string,password:string}，带X-CSRFToken | 成功200返回同一会话对象，设置HttpOnly会话cookie，轮换会话及CSRF；认证失败401 INVALID_CREDENTIALS |
| DELETE `/api/v1/admin/session` | 无正文，带X-CSRFToken | 200，data={loggedOut:true}；撤销会话cookie，不要求普通访客登录 |

user为null或{id:string,displayName:string}；permissions为下述权限字符串数组；csrfToken非空，只用于管理写请求。Cookie在HTTPS下Secure，SameSite至少Lax；前端不把会话凭据存localStorage。管理接口建议只在既有私有服务/SSH隧道开放，不能把localhost地址和开放公网视为同一种部署。首个管理员通过后端安全初始化建立，本文不提供公开注册接口。

| 拟定权限 | 能做什么 | 现有能力依据 |
|---|---|---|
| articles.read | 读新闻/通知草稿和状态 | 查看Article |
| articles.edit | 新建、保存、提交审核 | 新增/修改Article |
| articles.review | 批准、退回、撤下 | review_article |
| materials.read / materials.edit / materials.publish | 查看/编辑/发布教师、栏目、固定块、站点、首页设置 | ContentEntry相关权限与publish_contententry |
| media.read | 选择可用素材 | 当前后台素材选择器 |
| audit.read | 查看操作记录 | 当前AuditEvent及后台日志 |

所有管理接口服务端验权限；登录不等于可发布。角色怎么分组由后端配置，同一账号可有多项权限，不能宣称代码强制双人审核。B1会话GET可匿名，其余B接口未登录401；登录失败要限速，不在响应中说明用户名是否存在。

### 管理对象和版本约定

`DraftMeta={id,label,revision,state,published,updatedAt}`：id是后端生成的稳定字符串、不同于slug；label为列表显示名；revision为非负整数；updatedAt为ISO8601时间或null；state按下表；published为null或 `{revision:integer,publishedAt:string}`。不返回密码或数据库内部字段。

`Draft<T>` = DraftMeta加 `content:T|null`。普通已创建对象content非null；尚未初始化的固定块/site/home可返回revision=0、state=draft、published=null、updatedAt=null、content=null，便于后台创建首版。未知资源ID仍404。

- 创建成功201并返回DraftMeta，revision从1开始；GET详情200返回Draft<T>；PUT保存/POST动作200返回更新后的DraftMeta。
- PUT为**完整可编辑内容替换**：`{expectedRevision:integer,content:T}`，不是任意部分PATCH。缺字段422，不默默清空；id、创建后的slug不可修改。
- 除新建外，每次写入都带expectedRevision，服务端在同一事务比较；不符409且不产生部分写入。成功保存或状态动作均推进revision一次。
- 发布在同一事务内复制完整可公开快照、更新状态/版本并记录操作者与时间；published.revision记为这次成功发布后的revision。编辑草稿不会改旧快照；state=draft时仍可能published非null。
- 不提供硬删除接口。撤下移除公开版本、保留草稿与日志；再次发布走正常流程。重复点击旧expectedRevision返回409，避免重复操作。

这套统一revision保护是新后端契约；旧系统只有Article有同款并发保护，ContentEntry尚无，不能把计划写成现状。

### B3. 提交审核、批准发布、退回、撤下新闻

统一POST `/api/v1/admin/articles/{id}/actions`，JSON为 `{action,expectedRevision}`。action只能为下表枚举；成功返回DraftMeta。提交/批准使用已保存草稿，未保存的本地表单不会自动带入。

| action | 允许状态 | 所需权限 | 新state与前台影响 |
|---|---|---|---|
| submit | draft | articles.edit | submitted；旧前台不变 |
| approve | submitted | articles.review | approved；完整复制快照，前台展示新版本 |
| return | submitted | articles.review | draft；保留旧快照，初次稿仍不可见 |
| withdraw | published非null | articles.review | draft，published=null；从所有公开入口撤下 |

状态不允许返回409 INVALID_STATE；版本不一致409 REVISION_CONFLICT；无权限403。既有系统允许的部分宽松状态操作不作为新接口的必需行为，按此明确状态表联调。

```json
{"action":"submit","expectedRevision":1}
```

收到成功后重新使用响应中的revision，例如变为2，再由审核账号：

```json
{"action":"approve","expectedRevision":2}
```

批准响应：

```json
{
  "data":{"id":"article-example-001","label":"【演示】新闻发布流程联调","revision":3,"state":"approved","published":{"revision":3,"publishedAt":"2026-10-15T10:02:00+08:00"},"updatedAt":"2026-10-15T10:02:00+08:00"},
  "requestId":"article-approve-example"
}
```

然后通过A4/A5、首页及 `/news-contract-example.html` 核对已发布版本。再修改草稿得到revision=4时，前台仍显示已发布revision=3；重新submit/approve后才更新。withdraw也必须取当前revision，成功后列表移除、详情404。流程必须记录创建、保存、提交、批准、退回、撤下的操作者和版本。

### B4. 教师与通用栏目内容维护

下表中的 `{resource}` 只取teachers或entries，复用一致协议，不强制共用一张表。

| 方法与路径 | 请求/返回 | 权限 |
|---|---|---|
| GET `/api/v1/admin/{resource}` | page/pageSize，默认20；可选slug精确匹配，entries还可按collectionId筛选；200分页DraftMeta[] | materials.read |
| POST `/api/v1/admin/{resource}` | {content:TeacherWrite或EntryWrite}；201 DraftMeta | materials.edit |
| GET `/api/v1/admin/{resource}/{id}` | 200 Draft<对应Write类型> | materials.read |
| PUT `/api/v1/admin/{resource}/{id}` | {expectedRevision,content}；200 DraftMeta | materials.edit |
| POST `/api/v1/admin/{resource}/{id}/actions` | {action:"publish"或"withdraw",expectedRevision}；200 DraftMeta | materials.publish |

TeacherWrite=`{slug,name,subtitle,summary,body,portraitUrl,source,sortOrder,awards,isDemo}`：name非空最长160，subtitle最长200，summary最长3000，Body.text非空最长30000；portraitUrl为B6选取的照片URL或null；source为Source|null；sortOrder非负整数；slug为teacher-开头的稳定小写标识（最长100）；isDemo为boolean，演示姓名加前缀。awards使用TeacherSummary相同结构，校验类别存在、关系不重复、年份可空且为四位年；资料id由后端稳定生成。发布后的name/subtitle/summary/body及awards完整投影到A8/A9，不截成卡片摘要。

EntryWrite=`{slug,collectionId,title,summary,body,coverUrl,source,displayDate,sortOrder,directionSlug,isDemo}`：slug为entry-开头最长100且创建后固定；collectionId为当前栏目映射表中的集合ID；title非空最长160、summary最长3000、body非空最长30000；coverUrl、source、displayDate同ArticleWrite，sortOrder非负整数；directionSlug为string|null，仅group-directory允许关联已发布research-directions条目。其他栏目必须null；发布时再次校验关联目标，失效返回422。

materials状态为draft/published/withdrawn。PUT保存变draft，旧公开版本保留；publish从任一状态复制有效草稿并变published；withdraw要求存在发布快照，成功变withdrawn、公开版本移除。无需新增新闻同款提交审核状态；发布权限仍单独校验。教师/条目撤下影响首页、列表、详情及相关课题组；草稿和原ID保留。创建后slug不改，移动栏目须校验新collectionId并保持旧详情URL有效。

迁移旧record-*条目时由后端映射保留原URL，不要求管理员把原正文重新录成多份。三位真实教师先完整迁入草稿并核对发布，不将其初始化为虚构教师。

### B5. 固定内容块、站点资料和首页配置

固定资源不提供重复新增列表；GET未初始化的已知资源返回revision=0、content=null。首次PUT用expectedRevision=0，后续用当前revision。未知blockId返回404。

| 资源路径（前缀均为/api/v1/admin） | GET返回 | PUT正文 | POST动作 |
|---|---|---|---|
| `/blocks/{blockId}` | Draft<BlockWrite> | {expectedRevision,content:BlockWrite} | `/actions`，publish/withdraw |
| `/site` | Draft<SiteWrite> | {expectedRevision,content:SiteWrite} | `/actions`，只允许publish |
| `/home` | Draft<HomeWrite> | {expectedRevision,content:HomeWrite} | `/actions`，只允许publish |

GET需materials.read，PUT需materials.edit，动作需materials.publish；状态/版本规则同B4。site/home不提供整站撤下，通过保存明确空值再发布实现清空可选字段。block撤下只让对应正文回到待提供，学院概况页本身仍200。

- blockId目前为school-introduction、organization、leadership。BlockWrite=`{summary,body,coverUrl,source}`，summary最长3000，Body.text非空最长30000，coverUrl为素材URL|null，source为Source|null。概览中集合块的数据来自entries，不重复维护另一份正文。
- SiteWrite字段与A1相同，但logo改为logoUrl，wechat.qrCode改为qrCodeUrl，其余结构不变；两者为素材URL|null。universityName和collegeName非空且不重复前缀；phone/address/email/motto/备案/公众号可空；电子邮箱非空时验证格式。不能填写编造备案号。发布后页头、页脚与联系页读取同一快照。
- HomeWrite=`{slides,research,education,teacherEmptySlotCount}`。不接受news/notices/teachers正文，这些由已发布内容聚合生成，避免维护双份。
- HomeWrite.slides固定6个稳定槽id，字段为 `{id,enabled,sortOrder,theme,title,eyebrow,text,note,imageUrl}`；enabled为boolean，sortOrder非负整数，其余文本及theme同A2；关闭时保留草稿，公开A2过滤掉；chip主题可无图。相同sortOrder按id稳定排序，不传轮播总数。
- HomeWrite.research结构同A2 ResearchFeature，但topics每项为 `{columnId,title,imageUrl}`，代替Media；education同A2 EducationFeature，但image改为imageUrl。所有图片从B6选取；links/topics的columnId需真实有效。teacherEmptySlotCount为非负整数，对A2和A8共用。

站点、轮播、首页介绍的文本/图片都需要真实后台维护位置；不能只设计一个GET读取接口，却把值永久写死在后端。导航、装饰、布局不在这些内容表里，避免后端改内容时破坏队友设计。新增动态标题文字还需前端核对字体子集或回退覆盖，不能假定现有104字覆盖任意新文案。

### 从零实现的业务边界

建议逻辑上区分账号/权限、草稿、已发布快照、栏目归属、素材和审计，不要求这些恰好对应六张表。页面只读发布版本，不能直接查草稿表并靠前端隐藏。管理修改的响应必须与真实持久化结果一致；先事务提交再报成功。所有管理操作不得在GET中产生写入。

账号分配、存储选型和管理框架由后端决定；不实现学校SSO替代品。新API路径、session方案和状态表是可评审的默认方案，若后端已有等价规范须在联调前统一修改本文，而不是接口一处改名、前端另一处猜测。
