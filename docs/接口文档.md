# 后端接口与前端对接文档

核对日期：2026-10-15。依据当前工作区源码编写；提交与部署状态统一见 [STATUS](../STATUS.md)。本文描述已经实现的接口，不代表服务器已经升级。

## 1. 接口在哪里

当前架构为服务端渲染：浏览器请求 HTML 页面，Django 读取已发布数据并渲染模板。前端交互脚本操作 DOM，没有新闻、教师或栏目的 REST 请求。`/healthz` 是现有的 JSON 健康检查接口。

| 要找的内容 | 实现入口 |
|---|---|
| HTTP 地址注册 | [backend/config/urls.py](../backend/config/urls.py) |
| 页面、资源、健康检查、404/CSRF 错误响应 | [backend/content/views.py](../backend/content/views.py) |
| 公网只读、后台访问边界 | [backend/content/middleware.py](../backend/content/middleware.py) |
| 新闻草稿、审核与快照 | [models.py](../backend/content/models.py)、[services.py](../backend/content/services.py)、[admin.py](../backend/content/admin.py)、[forms.py](../backend/content/forms.py) |
| 教师、栏目、轮播、站点资料维护 | [entry_admin.py](../backend/content/entry_admin.py)、[editable.py](../backend/content/editable.py)、[collections.py](../backend/content/collections.py) |
| 前端公共组件和 DOM 契约 | [frontend/CONTRACTS.md](../frontend/CONTRACTS.md) |
| Django 数据适配层 | [frontend/scripts/adapters/django.js](../frontend/scripts/adapters/django.js)、[backend/content/presentation.py](../backend/content/presentation.py) |

没有 `/api/news`、`/api/teachers`、上传接口、搜索接口、学校 SSO 或博达同步接口。不要将内部 Python 函数、构建产物 `content-catalog.json` 或 `data-boda-slot` 标记当作可调用的网络 API。

## 2. 地址与公共约定

- 本地动态预览默认基址 `http://127.0.0.1:8095`，启动方法见 [后台 README](../backend/README.md)。后台数据要通过这个动态服务查看。
- `http://127.0.0.1:8766` 是可选的静态预览，根目录为 `frontend/preview`；不提供后台、健康检查和发布数据查询。双击 HTML 同样仅为静态预览。
- 服务器地址、服务和最新版本见 [部署说明](../deployment/README.md) 与 STATUS。学校博达是另一套系统。
- 以下前台路由允许 GET、HEAD。正常响应为 `text/html; charset=utf-8`，资源、robots 和 health 另列。HEAD 不返回正文。
- 正常页面不要求登录；只读取已发布快照，草稿不可见。HTML 响应不缓存（`Cache-Control: no-store`）。
- 正文是纯文本：空行分段，`## ` 小标题须独占一段，HTML 转义，不支持完整 Markdown。
- 动态 URL 从站点根路径访问；目前没有验证挂在 `/college/` 等子路径下的部署。不能只迁移 HTML 而漏掉 CSS、JS、素材或模板。

## 3. 前台 HTTP 路由

| 路由 | 参数与数据来源 | 返回与缺省行为 |
|---|---|---|
| `/`、`/index.html` | 首页；新闻前 4 条、通知前 3 条来自 Publication；教师/轮播/站点资料来自适配层 | 200 HTML；空列表显示占位或空态 |
| `/news.html` | `page` 可选；已批准学院新闻 | 200 HTML；每页 10 条 |
| `/notices.html` | `page` 可选；已批准通知公告 | 200 HTML；每页 10 条 |
| `/<栏目 slug>.html` | 栏目目录中定义的集合，例如 `/admissions-section-3.html`（就业指导）、`/science-innovation-section-1.html`（研究方向） | 200 HTML；cards 每页 9 条，list 每页 10 条；支持 `page` |
| `/entry-<标识>.html` | 已发布栏目条目 | 200 HTML；未发布、撤下或不存在为 404 |
| `/record-<旧位置标识>.html` | 原固定位置内容的兼容详情，例如点号转换为短横线；由集合适配器生成 URL | 同上；不应自行猜测 URL，使用条目的 `url` |
| `/faculty.html` | 默认三位教师与已发布教师覆盖/新增数据 | 200 HTML；按排序值、key 排序，发布撤下设置后隐藏 |
| `/teacher-<标识>.html` | 对应可见教师，例如 `/teacher-cheng-gang.html` | 200 HTML；不存在或已撤下为 404 |
| `/contact.html` | 已发布站点资料与默认值 | 200 HTML；缺资料使用占位 |
| 固定页面，如 `/about.html`、`/talent-cultivation.html`、`/site-map.html` | 生成目录中 kind 为 page/overview 的白名单 | 200 HTML；固定块/栏目摘要通过模板读取已发布内容 |
| `/news-<标识>.html`、`/notice-<标识>.html` | Publication 快照 | 200 HTML；仅有草稿、已撤下或不存在为 404 |
| `/404.html`、其他未知路径 | 错误页；`404.html` 不在内容白名单 | **动态服务返回 404**；静态服务器直接访问实体 404.html 时通常返回 200 |
| `/healthz` | 无参数；执行一次 Publication 存在性查询 | 200 JSON；只说明进程能处理请求并完成该数据库查询，不代表全部业务/素材/发布流程健康 |
| `/robots.txt` | 无参数 | 200 text/plain：`User-agent: *` 与 `Disallow: /` |
| `/css/<文件>`、`/js/<文件>`、`/assets/<文件>` | 运行资源，支持 `?v=<内容哈希前12位>` | 200 对应 MIME；缺文件/扩展名不允许为 404；缓存 300 秒 |

分页使用 `Paginator.get_page`：省略或非整数 → 第 1 页；超出范围或小于 1 → 最后一页；空列表仍有第 1 页。没有 pageSize、筛选和公开搜索参数。新闻通知按展示日期、批准时间、主键倒序；集合按 sort_order 升序、日期倒序、key 升序。日期缺失显示“日期待提供”。

资源只接受单层文件名 `[A-Za-z0-9_.-]+`。CSS 只允许 `.css`，JS 只允许 `.js`；assets 允许 jpg/jpeg/png/svg/webp/woff2/ttf。前台资源路由可返回 SVG 和字体，不等于后台图片选择器也允许这些类型。样式版本值用于浏览器更新缓存，服务端不校验查询字符串，而是读取当前文件。

健康检查响应：

```json
{"status":"ok","mode":"local-preview"}
```

`IC_PUBLIC_ONLY=1` 时 mode 为 `public-readonly`。不额外返回新闻数据、数据库内容或凭据。

### 只读调用示例

先启动动态预览；Windows 中使用 `curl.exe` 避免 PowerShell 别名差异：

```powershell
curl.exe -i http://127.0.0.1:8095/healthz
curl.exe -i "http://127.0.0.1:8095/news.html?page=2"
curl.exe -I http://127.0.0.1:8095/css/style.css
curl.exe -i http://127.0.0.1:8095/teacher-cheng-gang.html
curl.exe -i http://127.0.0.1:8095/404.html
```

第二、四、五项返回 HTML，不应调用 `response.json()`。浏览器业务导航直接使用真实 `<a href>`；仅健康接口可以 `fetch('/healthz').then(response => response.json())`。

## 4. 后台表单接口

以下是 Django Admin 页面与表单，并非提供给新前端调用的 REST 接口。不从浏览器脚本直写数据库，不通过构造 POST 批量填充演示内容；日常录入按后台网页保存、审核/发布流程操作。

### 地址、认证与权限

| 地址 | 方法 | 用途 |
|---|---|---|
| `/preview-admin/` | GET | 管理入口；本机未登录时 302 到登录页 |
| `/preview-admin/login/` | GET / POST | 登录表单；采用 Django session 与 CSRF，不使用 Bearer token |
| `/preview-admin/content/article/` | GET | 草稿列表 |
| `/preview-admin/content/article/add/` | GET / POST | 新建草稿 |
| `/preview-admin/content/article/<id>/change/` | GET / POST | 编辑草稿；id 是内部数据库主键，与详情 slug 不同 |
| `/preview-admin/content/article/<id>/review/` | GET / POST | 核对草稿、批准/退回/撤下 |
| `/preview-admin/content/contententry/` | GET / POST | 资料列表；POST 为后台批量动作，包括 publish_selected |
| `/preview-admin/content/contententry/add/` | GET / POST | 新建教师、栏目条目或固定位置资料 |
| `/preview-admin/content/contententry/<id>/change/` | GET / POST | 修改资料草稿，保存不会自动发布 |
| `/preview-admin/content/publication/`、`/preview-admin/content/auditevent/` | GET | 发布快照、新闻操作记录；需对应查看权限，不提供编辑/删除 |

- 管理员须为 active/staff，具备对应模型权限；新闻审核另需 `content.review_article`，资料发布另需 `content.publish_contententry`。不能用一个“发布权限”代替两者。
- 表单编码为标准 HTML 表单，需 session cookie 和 `csrfmiddlewaretoken`；字段来自实际网页。不是 JSON 请求体。
- 公网只读模式：所有 `/preview-admin...` 请求与非 GET/HEAD/OPTIONS 请求均返回 404。普通模式的后台还检查直连客户端 IP，只允许 loopback；其他来源 403，不信任伪造的 X-Forwarded-For。
- SSH 隧道连接方式见部署 README；不开放公网后台。GET/HEAD 以外方法即使通过只读边界，也不等于业务视图支持（例如 OPTIONS 到 health 为 405）。

### 新闻与通知字段

| 字段 | 类型/限制 | 含义 |
|---|---|---|
| slug | slug，最长 80 | 必须 news- 或 notice- 开头；创建后固定；不要与现有路由冲突 |
| category | news / notice | 学院新闻 / 通知公告 |
| title / summary | 文本，最长 160 / 400 | 标题、摘要，必填 |
| body | 纯文本，最长 30000 | 正文，必填 |
| source | 文本，最长 100 | 来源 |
| date | YYYY-MM-DD，可空 | 展示日期，非批准时间 |
| image / image_alt | 图片白名单文件名 / 最长 200 文本 | 配图和说明；白名单见 models.py 的 IMAGE_CHOICES |
| is_placeholder | 布尔值 | 标记待确认示例；不会自动给标题加【演示】，录入者需填写 |
| expected_revision | 隐藏整数 | 新建为 0；编辑/审核使用打开页面时的版本，不自行猜测 |
| submit_for_review | 布尔值 | 仅保存草稿，或保存后提交审核 |

审核表单字段为 `expected_revision` 和 `decision=approve|return|withdraw`。approve 只批准已提交草稿；将内容复制到 Publication。return 保留旧快照；withdraw 删除公开快照但保留草稿。保存草稿不改变前台已批准版本。上述操作带事务和 AuditEvent，均禁止在后台删除草稿。

保存版本冲突可能以表单错误（200 HTML）或 409 文本返回；审核冲突/状态错误显示在审核表单（200 HTML）。成功通常 302 跳转。不能仅凭 HTTP 200 判断保存或发布成功，必须核对页面消息和前台结果。

### 教师、栏目、站点与轮播字段

资料使用 ContentEntry；不是新后端必须照抄的表结构。

| 用途 | 标识与主要字段 |
|---|---|
| 新增教师 | 后台选“新增教师”，teacher_slug 填 `teacher-...`；title 姓名、subtitle 职称、summary 简介、body 完整内容、image 照片、sort_order 排序 |
| 栏目条目/方向/平台/课题组 | 选“新增栏目文章”，teacher_slug 填 `entry-...`；collection 从目录选择；title、summary、body、date、image、source_label/source_url；课题组的 direction 可关联一个已发布方向 |
| 固定区块/轮播 | key 从生成的 slots 选择；旧 key 保留，例如 `about.section-1`。字段映射见目录 defaults 与适配器 |
| 站点资料 | key=`site`；college（不含“河南大学”前缀）、english、motto、image/image_alt（标识）、address、phone、email、account_name、qr_image、body（页脚备案说明） |

key 最长 100，保存后固定；title 最长 160；subtitle/image_alt/source_label 最长 200；summary 最长 3000；body 最长 30000；date 可空；sort_order 非负，默认 100。图片与二维码从当前运行 assets 的 jpg/jpeg/png/webp 选择，没有上传。

保存后在列表选择资料并执行“发布到预览前台”，才更新 published 快照。撤下教师/条目需要关闭 is_visible，再执行发布。ContentEntry 没有新闻同款独立审核状态机、revision 并发保护或 AuditEvent；Django Admin 有操作日志。默认教师无覆盖时保留公开资料；轮播关闭会回退默认，并不会真正移除；站点部分空值回退默认，不能承诺主动清空。

## 5. 后端替换时的展示接口

下面是现有模板输入及适配边界，不是已经提供的 JSON endpoint。新后端可使用自己的数据库和权限模型，输出同样的展示数据与 HTML；若改为客户端请求，则还需另行实现 API、错误处理、加载状态与组件挂载生命周期。

| 模板输入 | 已有字段与语义 | 当前生产方 |
|---|---|---|
| 页面外框 | page_heading、page_english、active_page（例如 faculty.html）、breadcrumbs 数组（href/label；不含模板自行输出的首页和当前页） | presentation.page_context |
| site_info | name、college、english、motto、image/image_alt、body、address/phone/email、account_name/qr_image | editable.site_context；默认目录 + 已发布非空覆盖 |
| teachers | key、title、subtitle、summary、body、image、source_url/source_label、sort_order、is_visible | editable.teachers；默认资料 + 已发布覆盖，过滤撤下项 |
| collection | id、key、slug、url、title、layout、parents、active、legacyKeys 等目录字段 | collections.definitions/get_collection |
| 栏目 items | key、url、title、summary、body、date、image/image_alt、source_label/source_url、direction、sort_order | collections.items；仅发布快照；摘要缺省取正文前 160 字 |
| 新闻列表 page / 详情 article | 分页对象、ArticleFields 展示字段；详情不读草稿 | views.listing/detail_or_page，读取 Publication |
| 轮播 | 六个固定位置；title/subtitle/summary/body/image/image_alt/is_visible | content_slots + Django slide 适配器 |
| 错误页面 | page_heading/page_english、error_heading、message；HTTP 状态由视图设置 | not_found/csrf_failure，共用 error-body 组件 |

例如，教师详情的外框上下文（示意值，不是 HTTP 返回）：

```json
{
  "page_heading": "程纲",
  "page_english": "FACULTY",
  "active_page": "faculty.html",
  "breadcrumbs": [{"href": "/faculty.html", "label": "师资队伍"}]
}
```

前端组件模板 `teacher-card` 接受 href/title/subtitle/summary/image；`collection-card` 接受 href/title/summary/meta/action/image。文本先转义，image 等结构字段由可信组件渲染，不能直接传入用户 HTML。具体 DOM、具名槽位、导航状态与 reduced-motion 要求见 [CONTRACTS](../frontend/CONTRACTS.md)。

对接时保留稳定栏目 id、原 URL、父子层级和旧 key 映射；不要把排序下标当标识。栏目定义修改后运行构建，同步静态预览、Django generated 模板和 content-catalog.json；运行中的 Django 缓存目录，更新后需重启本项目服务。动态正文不写回静态 HTML，catalog 不是业务数据库备份。

## 6. 错误与资源排查

| 现象/状态 | 实际含义 |
|---|---|
| 404“页面走丢了” | 未知路径、内容未批准或已撤下；不要为消除 404 绕过发布边界 |
| CSS 未加载 | 检查当前是静态还是动态入口、CSS 响应状态/MIME、完整部署资源与版本；看到 404 文案本身不能证明 CSS 失败 |
| 深层错误路径 | 动态外框的 CSS/JS/assets 使用根相对 URL，不应解析成 `/missing/css/...` |
| 403 CSRF | 渲染“请求未通过验证”；本次没有保存。非本机后台访问的 403 是边界中间件的简单文本响应 |
| 405 | 只读视图收到不支持的方法；公网写入可能先被边界拦为 404 |
| 409 | 新闻保存竞争或数据库锁冲突；重新读取内容后处理，不覆盖他人版本 |
| 400 / 登录失败 | Host 不在允许列表、表单验证或认证问题；查看实际响应，不硬改路由解决 |

静态 404 与动态错误正文均由 `frontend/src/templates/components/error-body.html` 生成；样式源为 `frontend/src/css/components/error-page.css`。只编辑源码，运行 `node frontend/scripts/build-site.js`；不手改 preview/generated，也不手填 CSS 版本号。

## 7. 验证与未实现项

`frontend/scripts/check-django-presentation.py` 使用全新 sandbox 空数据目录验证动态页面、404/深层404的CSS状态/MIME/哈希、CSRF页面、health与管理边界，再运行现有 Django 测试。测试记录见 STATUS。它不录入真实业务内容，不证明公网已部署，也不能替代浏览器视觉或多人后台操作验收。

尚未实现：业务 REST API、上传/附件、搜索、SSO、完整英文版、学校博达组件绑定和数据同步。接口设计或模型若有变更，更新本文及相应测试；不要在文档中预先宣称实现。博达的材料与试点边界另见 [BODA-HANDOFF](../frontend/BODA-HANDOFF.md)。
