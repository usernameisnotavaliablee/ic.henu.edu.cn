# 学院网站前端开发确认方案

日期：2026-10-15｜状态：确认后的前端已在原开发分支实施，验收证据见 STATUS｜范围：前端页面、展示数据契约、接入说明与本地验收

本方案依据两份会议转录及用户逐项回答整理。用户已将栏目树发给老师并获“可以”的反馈；其后又确认了人才分类、样式、排序、判空、首页交互和内容维护方向。就本轮明确纳入的前端工作，理解置信度已达到用户要求的 95% 以上；这个判断不表示平台能力、正式资料或暂缓事项已经确认。

**后续开发以本方案的确认结果为准。** [会议需求说明](会议需求说明_20261015.md)及[证据索引](内部资料/会议需求证据索引_20261015.md)保留为详细背景，原稿中的待确认问题按本文更新，不再重复询问已确认事项。

## 1. 本轮范围与平台事实

- 先把前端做好，沿用已合并 main 的视觉与重构组件。
- 所有日常可更新内容都要有明确数据接入位置、字段及展示规则。最终内容维护方向为博达；本地 Django 保留开发预览用途。
- 博达后台由谁负责实施、是否由本轮一起操作尚未决定。本轮不登录博达配置栏目、录入内容或发布，也不扩建 Django 业务后台、运行数据库迁移。
- 用户确认学校域名 `icme.henu.edu.cn` 已能预览整站界面；后台新增新闻后能否同步首页、列表、详情尚未验证。不得将“界面可预览”写成“动态维护链路已完成”。
- 按后续明确要求，本科生招生、研究生招生、就业指导上移到人才培养的直接下级，首次展开即可见；旧页面/数据key保留。招生与培养的最终拆分和名称仍待明确，不能以此延后入口上移。
- 本方案形成时，main 与 origin/main 均为 f59755f，fetch 成功；既有未提交文档与本地资料保持原样。此时尚未开始本方案的页面实现。

## 2. 栏目调整

### 2.1 学院概况

以下结构已经用户明确确认：

```text
学院概况
├─ 学院简介
├─ 学术委员会
└─ 管理机构
   ├─ 领导班子
   ├─ 党政机构
   ├─ 教授委员会
   └─ 工会
```

学术委员会与教授委员会是两个独立机构。先按上述名称和层级搭建，具体成员、分工和职责等待学院正式材料，不把转录中的口头解释直接放入官网。

### 2.2 师生园地与制度归并

- 师生园地继续在人才培养下，保留师生活动、学生风采，新增团学建设。
- 统一使用“制度建设”名称，承接教师、学生相关制度及办事流程。
- 制度按**发布日期倒序**展示。发布日期由内容数据提供，不用上传时间替代；补录旧文件不会自动占据最新位置。
- 撤去公共服务一级栏目及对应展示入口。将现有制度和流程的展示归属映射到师生园地，不在本轮擅自清理或改写已有业务数据。
- 原公共服务下的服务指南、网站导航不再作为该菜单的子项。已有旧地址、404 恢复入口及功能性网站地图分别处理兼容，不因删除菜单造成死链。

### 2.3 其他栏目

- 科学与创新继续保留研究方向、研究平台、课题组、研究进展、学术交流、芯片天地、大型仪器。
- 新闻通知继续保留学院新闻、通知公告、媒体掠影。
- 党建党务保留当前简洁结构；人才招聘、联系我们保留。
- 人才培养顺序：本科生招生、研究生招生、学科与专业、课程与培养方案、工程教育认证、就业指导、师生园地；不再通过“招生就业”子菜单进入。本研招生与培养最终拆分暂缓。
- 科研页课题组进入正文大区块，读取原课题组集合预览，提供列表入口；不再放在相关栏目中。
- 导航、正文入口、当前项和面包屑关系统一来自栏目定义，保持主线已有交互样式，不再各处手写一份层级。

## 3. 师资分类、数据关系与呈现

### 3.1 分类及固定优先级

采用纳米学院参考顺序，保留以下六类：

| 优先级 | 人才分类正式展示名称 | 栏目内部展示 |
| --- | --- | --- |
| 1 | 国家级领军人才 | 大幅竖向长方形头像、姓名、职称、简介摘要 |
| 2 | 国家级青年人才 | 大幅竖向长方形头像、姓名、职称、简介摘要 |
| 3 | 河南省特聘教授 | 小圆形头像、姓名、职称 |
| 4 | 河南大学“黄河学者”/明德特聘教授 | 小圆形头像、姓名、职称 |
| 5 | 河南大学校特聘教授 | 小圆形头像、姓名、职称 |
| 6 | 河南大学百人计划 | 小圆形头像、姓名、职称 |

“河南大学‘黄河学者’/明德特聘教授”是一个类别，不拆分。中原学者、新世纪人才、攀登计划及杰出人才特区支持计划第三／第四层次不加入本轮分类；原有“其他高层次人才”不作为上述六类的替代。存在旧分类值时必须保留兼容记录，不能直接丢人。

普通教师采用紧凑姓名列表，点击进入个人详情；教师名录保留作为完整资料入口。国家级人才的竖向照片建议 3∶4，简介摘要控制在两三行，完整资料保留在详情页。

### 3.2 一人多称号与年份

- 同一教师可以同时属于多个经学院核准的人才分类。
- 各分类引用同一教师身份和详情地址，只维护一份简历；不复制个人介绍。
- 获评年份绑定到“教师＋称号”的关系，而不是教师全局只有一个年份。允许选填；有值可显示“程纲（2015）”这样的形式，无值不显示空括号。
- 在不同分类中，同一教师可使用对应分类的不同卡片样式；照片、姓名、职称和正文仍来自同一资料。
- 正式归类、年份及新增教师信息以审定材料为准。本轮不根据示例或公开旧履历擅自认定现有教师称号。

建议前端契约分为三个对象，具体实现字段名可与现有契约协调：

| 对象 | 需要表达的内容 | 约束 |
| --- | --- | --- |
| 教师 | 稳定 ID、姓名、头像、职称、简介摘要、完整资料、显示顺序、发布可见性、详情地址 | 一人一份资料；不能用姓名作为唯一标识 |
| 人才类别 | 稳定 ID、名称、优先级、启用、展示档位 | 六类顺序固定为当前确认基线；新增能力保留接入口 |
| 教师称号关系 | 教师 ID、类别 ID、可选获评年份 | 同一关系不重复；支持一人关联多类 |

这是前端接入契约，不是宣称已在博达或现有 Django 建好对应字段。

### 3.3 排序和完整性

- 三位现有教师的默认顺序确认为：**程纲 → 郑海务 → 张锦龙**。
- 保留三人完整资料，不能为适配卡片摘要删减详情。
- 需要按人才级别排序的展示中，以六类优先级为第一排序依据，同层级使用可调整的展示顺序；初始人工顺序按上条。
- 同一教师拥有多种称号时，首页按其最高优先级称号判断位置。
- 未分类不等于普通教师：不能因为缺分类字段就擅自认定身份。未分类教师仍保留在完整名录；其资料归类待正式数据提供。

### 3.4 分类判空

- 对每个分类，先筛选已发布且可展示的教师，再判断是否为空。
- 按10月15日追加要求，国家级领军人才、国家级青年人才无人时仍保留标题和“相关内容正在整理中”；其余类别无人时隐藏标题和整个内容块，不生成虚构教师卡片。
- 有符合条件的教师时显示；最后一位撤下后应重新隐藏。
- 分类配置本身保留，不因为前台为空而删除类别定义。
- 个人详情的可选内容为空时，不输出“无”或一串空小标题。

## 4. 首页调整

### 4.1 师资板块

- 保留现有首页“头像＋简介”卡片视觉，三档师资样式用于师资栏目内部。
- 首页最多展示 **3 位**，按人才优先级选择；其后为普通教师。未分类资料保留可见性，具体归类未提供时沿用现有已审阅资料顺序，不猜称号。
- 按教师稳定 ID 去重，同一人拥有多个称号也只占一个位置。
- 同层级按展示顺序；更多教师从“查看师资队伍”进入完整名录。
- 固定空位不能在实际教师数量增长后继续作为永久业务数据存在；空态按第 6 节处理。

### 4.2 移除重复快捷入口

删除首页近页脚处“学院概况／公共服务／人才招聘”三块 quick-links 整组，不留下空容器。学院概况与人才招聘仍从顶栏及合理正文入口访问。

### 4.3 科研三张图文卡片点击范围

适用对象：走近晶圆与芯片、微纳加工与实验、认识半导体器件三张卡片。

- 按用户红框截图，**图片下方的整个文字区域均可点击进入相应栏目**，包括文字之间的留白；不是只让标题字符可点。
- 上方图片不承担跳转，卡片外围不扩大点击范围。
- “图片来源”保留独立来源说明入口，点击它不被整块链接截获。
- 实现时避免嵌套链接；整块入口和来源入口都能使用键盘访问，焦点清楚。
- 最上方轮播及纯装饰大图按会议要求仅展示，不承担页面跳转；正常新闻入口、研究平台／课题组文字入口及导航继续可用。

## 5. 联系页、友情链接与二维码

### 5.1 友情链接

放在**联系我们**页面，分“校内链接”“校外链接”。按10月15日追加要求，两组使用默认收起的抽屉，点击平滑展开，支持键盘及减少动态效果；不增加页脚下拉框。

校内链接初始清单：河南大学、教务处、人事处、科学技术研究院、实验室与设备管理处、校大型仪器共享平台、河南大学网站工作室。

校外链接初始清单：河南省教育厅、河南省科学技术厅、国家自然科学基金委员会、国家知识产权局。

河南大学网站工作室使用 `https://hdwzgzs.cn/`，页脚现有技术支持入口继续保留。其余链接实施时逐一核对官方名称和有效 URL；未确认的链接不猜地址、不显示假入口。各项预留名称、URL、分组、排序和启用字段。

### 5.2 公众号二维码

按10月15日追加要求，联系页和页脚的公众号缺图时保留虚线待提供框，有正式图片后替换。学院网站的空二维码卡片移除，配置入口保留，有图时再显示。院徽、院训、联系信息继续按原有设计保留接入能力；不使用虚构二维码。

## 6. 无内容时的统一规则

| 场景 | 确认后的前台规则 |
| --- | --- |
| 具体人才分类无人 | 两个国家级类别保留标题及整理中提示，其他类别隐藏整个块 |
| 公众号二维码未提供 | 按10月15日追加要求保留虚线待提供框；有正式图片后替换 |
| 学院简介、管理机构等普通栏目未提供正文 | 保留入口，简洁显示“相关内容正在整理中” |
| 普通栏目没有列表数据 | 使用一处简洁提示，不堆放空卡片 |
| 教师获评年份未填 | 不显示年份及空括号 |
| 教师详情可选段落为空 | 不输出空标题，不写“无” |
| 外链地址未核准或未提供 | 不输出假链接；已有内容仍可阅读 |

配置能力与前台是否显示分开：隐藏区域仍保留其数据接入口。静态审核页只展示诚实的空态和已有资料，不能用伪造内容冒充已发布学院数据。

## 7. 所有可更新内容的数据接入边界

前端不将日常业务内容分散写死在组件和页面中。每个内容位置交付以下说明：页面位置、字段与类型、数据来源接口位置、空值行为、排序与数量规则、点击目标，以及未来博达应在哪里维护。

| 内容域 | 本轮应预留的前端输入 |
| --- | --- |
| 站点品牌 | 中文院名、英文、徽标、院训、页脚信息 |
| 首页轮播 | 数组形式的图片、文字、替代文本、顺序、启用；数量随数据生成 |
| 首页各区 | 标题、摘要、图文、栏目入口、推荐内容来源 |
| 新闻／通知／媒体／党建／团学／招聘 | 标题、摘要、日期、正文、图片图注、来源、附件、详情地址、展示状态 |
| 学院／机构资料 | 名称、简介、正文、成员、职务、分工、图片、顺序；缺资料有统一空态 |
| 教师与人才 | 唯一资料、多个称号及各自年份、展示顺序、头像、摘要、完整简介、可见性 |
| 科研与仪器 | 方向／团队／平台／仪器资料、关联信息、图文、外部服务入口 |
| 制度与办事 | 标题、发布日期、适用对象、正文、附件、来源、详情地址 |
| 联系与链接 | 地址、公开电话邮箱、公众号／官网二维码、友情链接分组与排序 |

通过独立数据适配层将上述输入交给共享展示组件。这里的“接口”包含模板槽位、字段契约和适配位置；本轮不凭空承诺新 REST API 或特定博达组件语法。具体平台字段、上传能力、发布和撤下如何绑定，留待后续实际平台对接。

教师 Word 材料先统一收集模板，再在博达后台录入／粘贴、预览和发布。自动解析与批量导入不在本轮范围。仅为前端验证使用的临时数据须隔离、明确标识，不写入实际业务库或正式资料源。

## 8. 实施步骤与修改入口

1. **栏目与兼容关系**：在 `frontend/src/data/columns.js` 调整概况、管理机构、团学、制度归属和公共服务撤并；核对导航、面包屑及旧地址映射。本研招生入口直接放在人才培养首层，最终命名及招生与培养内容拆分暂缓。
2. **展示数据与共享组件**：在前端数据／适配层表达多称号、年份、分类优先级；复用教师资料、实现大照片卡片、小圆头像条目、姓名列表；不在不同页面各写一套人物数据。
3. **首页与空态**：统一首页前三名选择、去重、摘要及空内容处理，删除 quick-links，调整科研文字块点击范围。
4. **联系页**：加校内／校外友情链接分组，核对目标网址，处理二维码条件显示；保留当前页脚风格。
5. **接入清单与文档**：更新前端展示契约和所有可维护位置清单，提供资料收集字段；明确本地已实现、仅预留、待博达验证三种状态。
6. **构建与验收**：运行现有构建，同步静态预览和规定的生成外框；运行相关前端检查，浏览器核对多种数据状态与尺寸，交付统一审核入口。

源码修改在 `frontend/src`、构建／适配在 `frontend/scripts`，不直接手改 `frontend/preview` 或 Django generated 文件。本轮不新增 Django 多称号数据库结构或迁移；生成外框与旧适配边界保持可追踪，新数据能力不能描述为旧 Django 后台已经支持。
