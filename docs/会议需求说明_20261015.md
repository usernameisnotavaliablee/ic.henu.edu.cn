本次应继续使用当前主线的蓝白风格、响应式和共享组件，重点纠正栏目组织、师资分类与内容维护行为。无需推倒重写整站，也没有新的 React 迁移或自建学校后台要求。

## 3. 目标、范围与交付边界

### 3.1 本轮目标

1. 导航与栏目符合会议确认的业务组织，让访客能直接找到招生、培养、制度、教师和科研材料。
2. 保持主线已认可的整体视觉；减少重复入口、无内容大块占位和移动端误触。
3. 让学院在博达内维护日常内容，不依赖开发人员反复改网页文本。
4. 建立统一材料收集清单，区分真实学院事实、通用示意素材及内部演示内容。
5. 以实际博达发布页面和后台维护流程验收，不以本地静态预览替代正式平台结果。

### 3.2 本稿不直接触发的工作

- 不据会议转录编造领导名单、教师称号、仪器归属、招生计划和委员会职责。
- 不把本稿所列目标功能描述为当前 Django 或博达已经全部具备。
- 不要求复制 Django 数据库到博达，不预设博达开放 JSON API，不新增未经验证的接口地址。
- Word 自动解析、论文索引跳转、独立党建站、整站英文版均非本轮已定交付。
- 本轮仅编写需求与状态说明；页面修改、内容录入、发布、提交和推送未执行。

## 5. 页面、品牌与交互需求

### REQ-01 学院名称、英文与字体

**状态：会议明确；P0。来源：A 00:02:15、00:52:01、00:57:21、01:07:11—01:09:14。**

- 所有作为本学院身份标识的中文名称包含“（筹）”，包括页头、页脚、轮播院名、页面标题和分享摘要；不能全局替换所有“学院”二字，其他学院名称、文章历史引文不受影响。
- 英文名称后以逗号连接 Henan University。当前源码已为 `School of Integrated Circuits and Micro-Nano Electronics, Henan University`，正式译名仍由学院审定；不能照抄转录误识别的 `circus` 等词。
- 正文、导航等继续使用微软雅黑优先的系统字体；栏目展示标题沿用现有有许可证的宋体。全站风格一致，不额外导入商业字体文件。
- 英文品牌文字不等同于英文版站点；不因此增加无实际内容的中英文切换。

**验收：**核对首页、各类内页、教师详情、404、页脚和移动端的本院名称；不重复“（筹）”；英文断行不截断院名；新增标题在自托管字体子集中有字形。

**现状：**默认院名、英文及主要模板已处理；真实平台正文、图片内文字、分享字段和后台覆盖值尚未据本稿逐页验证。

### REQ-02 校徽、院徽、校训和页脚二维码

**状态：会议明确；P1。来源：A 00:02:15、01:05:52—01:06:34。**

- 现用校徽、校训可在学院正式院徽、院训确定后替换，页头和页脚保持一致。
- 页脚预留学院公众号二维码区域。当前已有的官网二维码位置继续保留为既有设计，不将“会议同意新增两种二维码”作为事实。
- 没有正式二维码时，不放假二维码或个人账号替代。材料未就绪期间可在内部审核版标明待提供；公开展示方案由学院确认。
- 申请主体和官方认证由学院协调，开发人员负责收到素材后的接入。会议未确定个人责任人，也未承诺申请完成时间。
- 保留当前技术支持标识及网站工作室链接，会议没有要求重做该设计。

**验收：**在博达维护位置修改标识／院训／二维码后发布，前台对应位置同步；图片等比显示；真机扫码进入正确账号或正式网址；未填写的可选二维码不留下失衡大空块。

### REQ-03 导航与移动端使用

**状态：会议明确方向，尺寸指标为建议；P0。来源：A 00:03:49—00:05:15、00:07:05、00:35:03—00:35:23；B 00:02:07—00:02:41。**

- 保留顶栏、现有多级菜单及克制的展开动效，不新增杂乱的顶级栏目。
- 桌面与窄屏采用各自适合的排布，不要求将桌面多层悬停原样搬到手机上。
- 展开子菜单与跳转页面的触发方式应清楚；手机滚动和收起菜单不能误跳。
- 对照参考网站“页眉过大、内容要向下找”的反馈，检查详情页首屏是否容易找到标题和正文入口；这是一项检查要求，不是已确定的全站页头高度重设计。

**验收建议：**1440、768、390、320 像素模拟宽度无横向溢出；手机／平板真机检查展开、返回、滚动、长院名；主要触控按钮建议不少于 44×44 CSS 像素；动画不阻断点击和键盘操作。

### REQ-04 首页重复入口与图片点击

**状态：重复导航应减少、大幅图片避免误触为会议明确；具体元素待圈定；P0。来源：A 00:40:58—00:43:38。**

- 首页已有新闻、通知、科学与创新、人才培养、师资区块，会议未要求移除这些主体内容。
- 取消公共服务相关首页入口。A 00:42:20—00:42:42 同意去掉与顶栏重复的“一栏”；当前源码最吻合的对象是首页末尾 `quick-links` 三入口块，实施前用截图确认对象。
- A 00:43:12—00:43:38 讨论大面积图片的链接容易误触，结论是不做这类图片超链接。
- 建议以“轮播／纯装饰大图不跳转，新闻标题和明确的阅读入口正常跳转”为实现规则；科研三张图文卡是否同属删除范围需要确认，不能一刀切删除所有图片链接。

**验收：**点击或触摸大幅装饰图不意外导航；新闻与通知仍能由标题进入详情；删除 quick-links 后正文至页脚间距正常，无遗留空容器；未删错内容区块。

## 6. 栏目与内容展示需求

### REQ-06 学院概况与管理机构

**状态：顶层结构明确，机构细目需核准；P0。来源：A 00:18:45—00:26:49。**

1. 学院概况下设学院简介、学术委员会、管理机构三个并列入口。A 00:26:49 是较后且清晰的结构复述，应优先于前面的试探性讨论。
2. “组织机构”统一改称“管理机构”；参考纳米学院的业务组织，不照搬全部页面风格。
3. 管理机构下保留领导班子，增加或细分党政机构、教授委员会、工会等。转录提到“这四个东西”但没有逐字完整列举，四项组合是依据前文还原，须确认最终名单和顺序。
4. 学术委员会与教授委员会分开建模和展示。毕业审核相关描述出现于“教授委员会”的讨论，不可写成学术委员会的确定职责；实际机构名称与职责由学院提供。
5. 学院简介、学术委员会不强行为占满层级再添加无意义子菜单；机构内容按资料量选择单页或名单进入详情。

**验收：**导航、概况正文、管理页面、面包屑和后台栏目归属一致；学术委员会不再只藏在管理机构下；没有复制两份同一机构正文；未确定的成员、职务和职责不编造。

**现状差异：**当前 `columns.js` 将学术委员会置于管理机构内，缺教授委员会、工会独立定义。修改后需要兼容原 `management-committee.html` 和已录入资料的对应关系，具体兼容方式见第 10 节。

### REQ-07 本科生、研究生及工程教育认证

**状态：入口应直接可见为会议明确；招生与培养拆分方式待确认；P0。来源：A 00:05:39—00:07:11、00:15:28—00:16:48。**

- 人才培养展开后，访客应直接辨认本科生与研究生信息；不能只有“招生就业”，再继续展开才能发现本科／研究生招生。
- 会议区分招生计划、专业介绍与后续培养方案，但没有最终确定是“本科生／研究生”两类汇总页，还是招生、培养分别列入口。
- 建议先将现有本科生招生、研究生招生提升至人才培养直接子项，保留学科与专业、课程与培养方案、就业指导；若学院希望按本科／研究生汇总，再统一调整，不同时维护两套相同内容。
- 工程教育认证纳入人才培养；栏目存在不意味着已经通过认证，未取得正式材料不得展示认证结论或有效期。
- 研究生可包含硕士、博士；不据这句话认定本院已具备全部招生资格或计划。

**验收：**桌面展开人才培养、手机展开对应一级菜单后能看见本科／研究生入口；现有文章可达；招生材料有正式来源、适用年度和发布日期；认证缺资料时不出现“已通过”之类无依据表述。

## 10. 实施建议与防止返工的规则

### 10.1 按依赖推进

1. **确认栏目与称号清单。** 先锁定概况机构、本研入口、制度合并、人才类别；对不确定项保留明确标记。
2. **修改唯一栏目定义与共享组件。** 在 `frontend/src` 调整导航、分类、空态、普通教师列表和首页重复块，复用已重构组件；不直接编辑 `frontend/preview` 或 Django generated 外框。
3. **处理旧入口和资料归属。** 建立旧 URL／旧栏目 → 新栏目清单；核对资料数量、正文与附件，再由维护人员迁移或重分类。
4. **同步博达展示与维护能力。** 在已可上线的平台配置栏目、模板和资料源映射，逐项记录字段从哪里改、发布后出现在哪里。
5. **材料录入、版式和平台验收并行。** 真实材料进入后台，缺项进入清单；保留审核版与公开版区别。
6. **学院确认与交接。** 依验收清单复核后发布获批准的内容，交付维护指引和人员分工。

### 10.2 内容与旧链接保护

- 删除菜单入口与删除数据是不同操作；本轮明确要求撤展示入口，不等于授权清空旧资料。
- 将学术委员会移出管理机构时保持资料身份不变，或提供经过核对的映射；不复制一条“新委员会”而遗留另一条旧正文。
- 对原公共服务、规章制度、办事流程及招生概览地址，可保留兼容页或转向新去处。博达是否支持相应重定向方式以实际能力为准，不承诺未经验证的配置。
- 404 恢复入口不能指向已删除页面；保留功能性网站地图与否需和“删除公开导航栏目”分别决策。
- 同一教师、制度、新闻一份主资料，多入口引用；尽量不复制正文，不将 UI 展示分类强制等同于数据库表。
- 真实材料从后台维护发布，不通过初始化脚本覆盖现有业务库；示例数据不得替代正式学院事实。
